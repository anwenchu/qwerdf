# $pd-fe — 前端开发实现

按本端顺序补通可核验的业务动作，集中处理相关改动与必要验证，再按原完成标准逐项回填。

## 读取

先按 [生命周期规则](../qwerdf-common/artifact-lifecycle.md) 读取续作入口并核对权威任务；以下材料按当前任务 / finding 读取相关有效段落与必要证据，引用失效或有新冲突再扩查，不重复通读全部历史；仅适用时读取数据模型、SQL 或 UI 材料，不要求无关文件。

1. 定位本 `SKILL.md` 目录为 `<skill-dir>`，运行 `python3 "<skill-dir>/../qwerdf-common/scripts/product_artifacts.py" context --stage fe`，只加载本阶段共享规则和模板（Python 3.10+，无第三方依赖）。不可运行时，按 [共享流程](../qwerdf-common/product-delivery-flow.md) 对应章节与下列模板手动读取，开工前读完 [验证与审查](../qwerdf-common/product-delivery-flow.md#验证与审查)；不通读无关阶段。
2. 开工时先读上述输出前置的完整验证与审查规则；若中转到文件，须读规则正文，不能只看 head 或检索标题后认定已加载。模板仅包含任务清单和共享业务进度摘要。默认把实现结果、检查与续作回写本端任务；任务选择、blocked 恢复和汇报按已加载共享规则执行。
   API 接入与任务范围按 [技术设计依据与范围规则](../qwerdf-common/technical-design-rules.md) 核对；关键参数 / 字段语义需猜测时回 `$pd-plan` 补证，不自行扩展契约或产品能力。
3. 读取 [UI Quality Checklist](../qwerdf-common/ui-quality-checklist.md)、[UI Patterns](../qwerdf-common/ui-patterns.md) 和 [UI Design System Rules](../qwerdf-common/ui-design-system.md)。
4. 读取 `tech/tech-plan.md` 的本端设计、契约、真实输入、接线与风险，以及 `tech/task-slices.md` 的本端任务及当前续作；涉及 UI / SQL 时补读其实际独立事实源及相关未决项，不因缺少旧分文件而补建整套材料。
   必须补读 Figma 原稿时，先加载当前环境中对应的 Figma 设计转代码技能并遵守其工具前置要求，连接选择与有效 session 按 [共享复用规则](../qwerdf-common/product-delivery-flow.md#figma-连接与会话复用) 执行，不因加载规范重新核查其他账号。已有材料不足时保留证据缺口，不用猜测或重复授权替代。
5. 如存在，读取 `sync/integration-report.md`、`sync/api-mismatch.md`、`test/test-report.md`、`test/code-review.md`、`ui/ui-review-report.md` 中归属 `$pd-fe` 的 findings。
6. 识别前端项目结构：`package.json`、路由、页面目录、组件目录、状态管理、API client、样式体系、测试命令。
7. 按 [共享目录规则](../qwerdf-common/product-delivery-flow.md#2-默认工作目录) 先确定本次独立任务根目录，以下阶段路径相对于该目录。

## 边界

- 只实现已授权且归属前端清单的任务，不改对端代码或状态、不单方面处理 contract、不引入未经要求的新框架。任务权威源、顺序、blocked 恢复与连续执行停止条件沿用已加载的共享规则；任务是状态归属单位，不强制每个小改动单独验证或汇报，也不是批量授权的结束点。
- 开始或重开前按 [设计交接规则](../qwerdf-common/technical-design-rules.md#3-交付应足以让实现者执行) 核对当前结论与决定性缺口；有依据且属于既有契约 / 本片的工程遗漏直接补齐，需改契约或范围回 `$pd-plan / $pd-figma`，真正业务取舍才问用户。只检查不启动开发。
- 依赖按当前动作用途判断，不等待对端业务实现或 SYNC；顺序 / 输入说明冲突回 `$pd-plan` 校正受影响记录，其他具备条件的本端任务继续。真正编码缺输入仍阻断；验证受限的可继续范围、真实状态与 done 标准按共享规则，禁止模拟替代或虚报通过。
- 缺陷修复按共享联调与验收交接规则：有契约 / 设计依据、实现证据及本端已有 slice 的 implementation-defect 才可重开；无覆盖或需改上游则回 `$pd-plan / $pd-figma`。空仓库可执行设计已交接且输入齐备的工程初始化。
- 涉及 UI 时使用已确认的设计系统、Figma handoff 和前端设计；不改上游事实源掩盖偏差。独立 UI finding 按 [修复交接](../qwerdf-common/ui-review-rules.md#6-ui-finding-修复交接) 核对证据和归属，不因旧报告缺工程字段拒绝修复。

## 前端实现 Quick Reference

优先检查高影响问题，再处理低影响优化：

1. 数据 waterfalls：独立请求并行，便宜同步判断放在 await 前，避免串行加载。
2. Bundle：避免无边界 barrel import，重组件按需加载，第三方脚本延后。
3. Server / client 边界：只把必要数据传到 client，避免重复序列化和共享可变请求状态。
4. 状态与重渲染：派生状态优先 render 中计算，昂贵计算才 memo，事件逻辑不要塞进 effect。
5. 组件架构：避免用多个 boolean prop 表达模式，优先明确 variant、组合组件或 provider。
6. 可访问性与响应式：键盘焦点、语义结构、移动端无横向溢出和 reduced motion 不可跳过。
7. UI 质量：本次目标平台布局、文本不重叠、设计系统一致性及适用状态的证据进入本端任务的验证记录；状态适用性按 [共享质量清单](../qwerdf-common/ui-quality-checklist.md#4-适用的状态与交互)，不适用写明理由。
8. 管理后台 / SaaS / CRM / 操作台：优先信息密度、扫描效率、稳定布局和可重复操作；不要把页面改成营销 hero、大面积装饰或低密度展示卡片。

## 流程

1. 读取续作入口、任务清单及本端顺序（默认只用 task-slices.md；JSON 例外先按共享规则核实实际工具消费），按 [共享仓库、分支与版本规则](../qwerdf-common/technical-design-rules.md#仓库分支与二方包版本) 核对实际目标及版本记录，再核对当前授权、设计交接与关联 finding。来源 / 状态冲突先按共享规则校正，视图滞后不能冒充任务缺失。
2. 按权威源中的本端顺序选择首个可执行业务动作，或有证据且已获准的缺陷修复；按共享验证规则沿用 / 确定收尾信号、最小检查和整个修改验证循环的剩余限额，输入齐备的相关改动集中处理。核查实际前置、全部原阻断及当前依赖用途；未 ready 只停止受影响动作。连续授权下转其他具备条件的任务，不以局部阻断全局停工。
3. 在原任务源更新本任务为 in_progress；按共享待办规则刷新项目 TODO；格式兼容例外另沿既有单向派生；同一批条目变化合并刷新，不随普通编辑重复执行。blocked 的解除及仅验证受限时保留 blocked 续作严格按共享规则，不修改他人状态，不直接跳到 done。
4. 按共享验证规则核对批次影响面，将相关页面、组件、状态、真实 API client、调用映射及旧测试同步迁移，包含权限 / 错误反馈和必要接线。将适用平台的布局、状态及设计系统一致性纳入本批检查，阶段收口时回填证据；已有独立 UI 报告则核对并引用有效复查结果。缺必要原稿或运行环境时注明影响，不猜设计或用样例代替真实页面验收。
5. 批次收尾时核对本轮受影响的实际生产调用及测试路径，检查是否仍有 mock / stub / fake / fixture-only / simulator 或未接入真实 client；未变路径复用有效核查，不随每次编辑全量重扫。命名只是线索，按实际行为确认，发现不能以模拟结果交付。
6. 按 [共享验证规则](../qwerdf-common/product-delivery-flow.md#验证与审查) 执行本业务批次的检查集合，覆盖各条目验收和原 finding，核对验证入口与当前产物对应；复用有效结果，再改 / 再跑及超时退出沿同一剩余限额，不对每个条目另起整套检查。
7. 在本轮覆盖的原任务条目分别回填简短实现 / 检查结果、证据、缺口和下一动作，变更路径引用 Git diff；不自动生成实现日志、changed-files、dev-notes 或验收副本。代码 / 接线及原最小验证均完成后才将原任务条目标 done；按共享待办规则刷新项目 TODO；格式兼容例外另沿既有单向派生；否则注明剩余代码与验证缺口，不用“外部受阻”掩盖未实现。
8. 按共享业务进度摘要回填目标、实现 / 接线、验证、剩余与阻断；对照上次已核实结果，核对原业务断点是否消失及剩余限额，触发纠偏时在原任务回填实际分流，不只写承诺。连续授权下回步骤 2。结束前核对原授权及所有剩余任务，只有满足共享停止条件才结束；不直接进入提交阶段。
