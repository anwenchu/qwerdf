# $pd-be — 后端开发实现

按本端顺序补通可核验的业务动作，集中处理相关改动与必要验证，再按原完成标准逐项回填。

## 读取

先按 [生命周期规则](../qwerdf-common/artifact-lifecycle.md) 读取续作入口并核对权威任务；以下材料按当前任务 / finding 读取相关有效段落与必要证据，引用失效或有新冲突再扩查，不重复通读全部历史；仅适用时读取数据模型、SQL 或 UI 材料，不要求无关文件。

1. 定位本 `SKILL.md` 目录为 `<skill-dir>`，运行 `python3 "<skill-dir>/../qwerdf-common/scripts/product_artifacts.py" context --stage be`，只加载本阶段共享规则和模板（Python 3.10+，无第三方依赖）。不可运行时，按 [共享流程](../qwerdf-common/product-delivery-flow.md) 对应章节与下列模板手动读取，开工前读完 [验证与审查](../qwerdf-common/product-delivery-flow.md#验证与审查)；不通读无关阶段。
2. 开工时先读上述输出前置的完整验证与审查规则；若中转到文件，须读规则正文，不能只看 head 或检索标题后认定已加载。模板仅包含任务清单和共享业务进度摘要。默认把实现结果、检查与续作回写本端任务；任务选择、blocked 恢复和汇报按已加载共享规则执行。
   关键接入与范围按 [技术设计依据与范围规则](../qwerdf-common/technical-design-rules.md) 核对；需要猜服务、方法、参数来源或字段语义时回 `$pd-plan` 补证，不静默发明契约或新增范围。
3. 读取 `tech/tech-plan.md` 的本端设计、契约、真实输入、接线与风险，以及项目已确认权威任务源（默认 `tech/task-slices.md`）的本端任务及当前续作；涉及 UI / SQL 时补读其实际独立事实源及相关未决项，不因缺少旧分文件而补建整套材料。
4. 如存在，读取 `sync/integration-report.md`、`sync/api-mismatch.md`、`test/test-report.md`、`test/code-review.md` 中归属 `$pd-be` 的 findings。
5. 识别后端项目结构：服务入口、路由 / controller、service、repository、数据模型、权限、错误码、测试命令。
   涉及 Java 实现时必读公共规范的 [结构与可维护性](../qwerdf-common/java-coding-rules.md#结构与可维护性) 和 [任务完成前自查](../qwerdf-common/java-coding-rules.md#任务完成前自查)，其余章节按改动读取；不将规范建议扩成新任务或另一套阶段门。
6. 按 [共享目录规则](../qwerdf-common/product-delivery-flow.md#2-默认工作目录) 先确定本次独立任务根目录，以下阶段路径相对于该目录。

## 边界

- 只实现已授权且归属后端清单的任务，不改对端代码或状态、不单方面处理 contract、不引入未经要求的新框架或存储方案。任务权威源、顺序、blocked 恢复与连续执行停止条件沿用已加载的共享规则；任务是状态归属单位，不强制每个小改动单独验证或汇报，也不是批量授权的结束点。
- 开始或重开前按 [设计交接规则](../qwerdf-common/technical-design-rules.md#3-交付应足以让实现者执行) 核对当前结论与决定性缺口；有依据且属于既有契约 / 本片的工程遗漏直接补齐，需改契约或范围回 `$pd-plan`，真正业务取舍才问用户。只检查不启动开发。
- 依赖按当前动作用途判断，不等待对端业务实现或 SYNC；顺序 / 输入说明冲突回 `$pd-plan` 校正受影响记录，其他具备条件的本端任务继续。真正编码缺输入仍阻断；验证受限的可继续范围、真实状态与 done 标准按共享规则，禁止模拟替代或虚报通过。
- 缺陷修复按共享联调与验收交接规则：有契约 / 设计依据、实现证据及本端已有 slice 的 implementation-defect 才可重开；无覆盖或需改上游则回 `$pd-plan`。空仓库可执行设计已交接且输入齐备的工程初始化。
- 涉及 Java 时按公共 Java 规则实现，持久化方式、MyBatis / XML、事务、行锁及缓存边界不得省略；按共享适用性回填需独立执行 / 审核的 SQL 计划，不执行未获准的 SQL。

## 流程

1. 读取续作入口、任务清单及本端顺序（项目已有约定优先，否则默认 task-slices.md；JSON 例外按共享规则核实实际消费），按 [共享仓库、分支与版本规则](../qwerdf-common/technical-design-rules.md#仓库分支与二方包版本) 核对实际目标及版本记录，再核对当前授权、设计交接与关联 finding。来源 / 状态冲突先按共享规则校正，视图滞后不能冒充任务缺失。
2. 按权威源中的本端顺序选择首个可执行业务动作，或有证据且已获准的缺陷修复；按共享验证规则沿用 / 确定收尾信号、最小检查和整个修改验证循环的剩余限额，输入齐备的相关改动集中处理。核查实际前置、全部原阻断及当前依赖用途；未 ready 只停止受影响动作。连续授权下转其他具备条件的任务，不以局部阻断全局停工。
3. 在原任务源更新本任务为 in_progress；按共享待办规则刷新项目 TODO；格式兼容例外另沿既有单向派生；同一批条目变化合并刷新，不随普通编辑重复执行。blocked 的解除及仅验证受限时保留 blocked 续作严格按共享规则，不修改他人状态，不直接跳到 done。
4. 按 [共享必要性规则](../qwerdf-common/technical-design-rules.md#现有能力与新增设计必要性) 对照方案核对实际结构及行为增量，需修订设计时先沿原交接处理。按共享验证规则核对批次影响面，将相关生产调用、装配、Mapper / XML 与旧测试同步迁移；实现接口、服务、持久化、权限、错误码、事务和真实下游接线，不留半套迁移后靠逐字段编译补齐。SQL / migration 文件进入原执行计划并引用 SQL ID。
5. 批次收尾时核对本轮受影响的实际生产调用及测试路径，检查生产路径是否仍有模拟替代或未接入真实 client；测试中的隔离替身按共享分层记录证明边界；未变路径复用有效核查，不随每次编辑全量重扫。命名只是线索，按实际行为确认，不能以模拟结果冒充真实交付。
6. Java 实现先按公共规范的 [任务完成前自查](../qwerdf-common/java-coding-rules.md#任务完成前自查) 检查实际改动，修正本片明确问题。自查范围以目标仓库的 `git status --short --untracked-files=all` 与本轮任务范围核对，覆盖相关已暂存、未暂存和未跟踪源码；未跟踪文件直接读完整内容。只有普通 `git diff` 时不能认定范围完整。按 [共享验证规则](../qwerdf-common/product-delivery-flow.md#验证与审查) 执行本业务批次的检查集合，覆盖各条目验收和原 finding，按共享分层核对独立预期、原失败的回归证据和实际接线边界，核对验证入口与当前产物对应；复用有效结果，再改 / 再跑及超时退出沿同一剩余限额，不对每个条目另起整套检查。
7. 在本轮覆盖的原任务条目分别回填简短实现 / 检查结果、证据、缺口和下一动作，Java 任务包含上述自查结论及保留项依据，变更路径引用 Git diff；不自动生成实现日志、changed-files、dev-notes 或验收副本。自查及相应问题处理、代码 / 接线和原最小验证均按要求完成后才将原任务条目标 done；按共享待办规则刷新项目 TODO；格式兼容例外另沿既有单向派生；否则注明剩余代码与验证缺口，不用“外部受阻”掩盖未实现。
8. 按共享业务进度摘要回填目标、实现 / 接线、验证、剩余与阻断；对照上次已核实结果，核对原业务断点是否消失及剩余限额，触发纠偏时在原任务回填实际分流，不只写承诺。连续授权下回步骤 2。结束前核对原授权及所有剩余任务，只有满足共享停止条件才结束；不直接进入提交阶段。
