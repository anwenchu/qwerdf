# Visual Defects Reference

用于定位可见问题；严重性和不能放行条件只在 [UI Review Rules](../../qwerdf-common/ui-review-rules.md) 维护。以下是检查线索，不是“一出现就 P1”的列表。

## 基础视觉缺陷

- 遮挡 / 重叠：固定区、浮层、toast、文本或 badge 压住内容与操作。区分预期 modal 遮罩与意外遮挡，说明受损任务及替代路径。
- 溢出 / 裁切：长中文、英文、金额、按钮和状态超出容器。区分可恢复的省略、局部滚动与关键信息永久不可获取。
- 风格不统一 / 字体不一致：同语义层级偏离 MASTER 的字号、字重、颜色、圆角或图标策略；允许响应式层级和批准变体，先排查字体加载与截图缩放。
- 右侧贴边 / 字段散落：关键数值和操作拥挤、label/value 关联不清；结合设计系统、点击目标和误读风险判断，不臆测精确 px。
- 对齐 / 间距：同类字段或操作缺少稳定阅读路径；内容自适应高度、跨行文字不必机械等高。

## 复杂信息展示缺陷

- 主识别信息、状态、关键指标和操作层级不清；金额 / 时间 / 百分比格式漂移。
- 同类卡片模板不一致且无业务理由，导致字段含义或操作位置难预测。
- 字段过多只压缩字号，没有分组、摘要、详情、展开或合适的局部滚动。
- 桌面表格直接塞进窄屏，造成页面级横向溢出或关键操作不可达。

## 状态与交互线索

- 适用的异步、错误恢复、权限或保存反馈缺失；empty 没有解释或合理下一步。
- 颜色成为唯一状态信息、危险操作与普通操作混淆、触屏关键动作只能 hover 发现。
- 这些行为需要相关状态截图或运行证据；默认截图看不到不代表状态不存在。

## Finding 示例

P0 · 创建页 mobile 375px：固定底栏覆盖唯一提交按钮，用户无法完成创建。证据为当前截图底部区域及页面操作验证；归 `$pd-fe`，修复后复查底部避让与相关表单组件。
