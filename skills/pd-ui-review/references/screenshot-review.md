# Screenshot Review Reference

用于用户截图、本地页面和前端验收证据。三层审查适用性、严重性、量化阈值及不能放行条件见 [共享规则](../../qwerdf-common/ui-review-rules.md) 和 [质量清单](../../qwerdf-common/ui-quality-checklist.md)。

## 证据与可比较条件

- 记录截图文件 / URL、页面、区域、视口与 DPR / 缩放（已知时）、状态、主题、语言、数据条件、版本或采集时间。用户未提供的信息写未知，不因此放弃可见问题审查。
- 浏览器取证使用代表性长文案、金额和错误反馈；按实际断点检查窄屏、布局切换处和宽屏。375px、768px、1024px、1440px 是无已有约束时的候选视口，不是每个项目必须跑的四项。
- 修复前后 / Figma 与实现比较先对齐页面、状态、数据、主题、字体加载、视口和版本目标。字体未加载、动态时间、动画或不同数据导致的差异先说明；掩蔽动态区域须记录范围，不能遮住被审查缺陷。
- 区分设计基线、独立组件样例和真实页面。样例通过不证明真实路由、固定栏和浮层组合后仍正确；必要时回真实页面检查。不得为得到好截图修改产品行为或绕过权限。
- 有完整原图时看整页，再放大关键区域；裁剪图不能证明整页。截图缩放未知时只描述可见拥挤 / 裁切，不猜“实际 CSS 边距为 12px”；精确尺寸依靠 DOM / computed style 或 Figma 节点。

## 三层截图审查

- 机器扫描：只有截图时 DOM、console、network 不适用；有运行页面时按本轮目标取证。键盘、隐藏状态、权限正确性和精确对比度不能从一张默认截图推断。
- 视觉扫描：主 CTA、固定区、表单、关键金额与错误提示是否可读可操作；长文本是否可恢复查看；局部表格滚动是否被误判为页面级横向溢出。
- 模板扫描：比较相关卡片、表格行、列表项的字段语义、操作位置和格式策略，允许多行文本、自适应高度及已确认 variant。
- 用户指出问题后记录相关页面 / 组件族 / 相邻断点的同类问题扫描，未覆盖范围明确列出；不把局部复查当全稿通过。

## 证据不足写法

- “当前只有桌面 default 截图；可审查可见布局，无法验证移动端、键盘和隐藏状态。”
- “当前仅有 handoff 自述，没有对应版本截图；修复状态未验证。”
- “紧凑边距符合 MASTER；未见关键内容裁切，不据默认像素值报 P1。”
