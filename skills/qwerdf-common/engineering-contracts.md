# Engineering Artifact Contracts

本文件定义工程阶段 skill 共享的产物模板。Skill 执行时只读取本任务需要的模板。依据、范围与交接判断统一见 [技术设计依据与范围规则](technical-design-rules.md)；按本轮风险选用下列记录，不为局部修订重做无关历史材料。

当前产物职责以 [阶段产物表](product-delivery-flow.md#1-交付链路) 为准；规模评估、证据留存、短记录及续作入口统一按 [生命周期规则](artifact-lifecycle.md) 处理，不把以下模板展开成逐轮日志副本。

默认产物以共享阶段表为准：下方主文档之外的分文件模板只供已有消费者、明确独立交付或必要主题详情定向使用，不能依次全部生成。内容优先作为主文档章节；存在旧事实源时引用，不再维护两份。

## 业务进度摘要

任务条目的简短结果及输出摘要共用以下结构；解释与完成口径统一按 [共享业务推进规则](product-delivery-flow.md#业务推进阻断恢复与进度汇报)，只填本轮适用范围，不复制整份需求或另算整体百分比。

```markdown
- 本轮目标：<里程碑 / 验收引用；本次业务动作、目标任务及阶段收尾信号；迁移批次引用原任务的待接通清单>
- 已实现与调用接线：<入口、关键状态变化、实际接入位置与仍未接通部分；相对上次已核实结果的增量，无增量如实说明>
- 验证：<批次检查覆盖哪些条目 / 要求，实际执行或引用的有效证据及未覆盖部分；临时入口说明当前输入 / 编译产物与实际执行范围的核对依据；纠错循环剩余限额 / 耗尽后的恢复条件；如有必要收尾，注明原位范围及退出条件；真实链路已验证 / 未验证，局部通过不算接通>
- 剩余与阻断：<未实现 / 未接线；契约缺口；依赖或验证阻塞，分别给位置、影响与下一步>
- 任务清单：<项目已确认的唯一任务源优先，无另行约定时默认 tech/task-slices.md；仅已证实工具依赖时注明例外来源与派生同步情况；只写本轮状态变化及剩余任务引用；用户询问统计时再按源列本端计数；代码已完成但待验证的项单独指出，项目 TODO 的刷新 / 只读核对结果及缺口（适用时）；派生视图滞后时注明>
- 继续或结束依据：<连续执行时下一项 ID、动作及预期结果；触发纠偏时写出原业务断点、已执行的分流及实际结果，不以同样计数或纠偏承诺替代；结束时逐项说明剩余项为何无获准可执行动作，或引用用户限定 / 暂停要求>
```

恢复 blocked 时，在原任务条目保留原阻断，并补解除证据、当前交接 / 依赖复核及状态变更；不新造恢复报告。

```markdown
## 依赖清单
| 依赖 ID | 类别 | 名称 | 适用 slice | 真实资源 / 地址 | 验证命令 | 状态 | 证据 | 阻断原因 | 下一步 |

```

状态枚举：

- `ready`: 真实依赖已可用，并有命令、连接、健康检查、版本或配置证据。
- `not-required`: 当前 scope 不需要该依赖，并说明原因。
- `unknown`: 尚未确认依赖是否存在或如何连接。
- `blocked`: 依赖已知不可用，缺账号、配置、网络、服务、版本或数据。
- `mock-only`: 当前动作所需的真实依赖仅有模拟替代，不能证明该依赖 ready 或相应真实链路通过；不用于否定允许的单元隔离测试，按共享验证分层判断。

仅多任务项目需要，复用已有总览；下面是两段可按需维护的导航表，不复制子任务状态。生成方法及失败处理只按 [共享待办规则](product-delivery-flow.md#项目待办视图)。默认派生模式的 `TODO.md` 由工具生成，不使用人工模板；项目已明确直接维护 TODO 等权威源时沿用其格式，不调用派生工具或补建 task-slices。

```markdown
## 任务索引

| 任务 | 范围 / 交付结果 | 验收引用 | 目录 |
| --- | --- | --- | --- |
| <稳定任务名> | <本任务结果> | <原验收定位> | tasks/<task-name> |

## 已确认待拆解

| ID | 事项 | 来源 |
| --- | --- | --- |
```

### 待办工具用法

仅在维护 / 核对多任务项目视图时读取本节及上方项目索引模板。原则和刷新时机只按 [共享待办规则](product-delivery-flow.md#项目待办视图)。

```bash
python3 "<skill-dir>/../qwerdf-common/scripts/task_todo.py" --root "<项目根目录>"
python3 "<skill-dir>/../qwerdf-common/scripts/task_todo.py" --root "<项目根目录>" --check
```

- 默认读取项目 `tech/task-slices.md`、`tasks/*/tech/task-slices.md` 及索引 `## 任务索引` 表中登记的项目内相对目录；等价索引用 `--index <项目内相对路径>`。不递归扫描历史。Markdown 标题允许标准的关闭井号；可识别的索引表落在未知章节时保留缺口，不猜归属或静默略过。
- 任务表沿本文件模板；来源可写“本文件”，也可用实际解析后指向当前 Markdown 的任务内 / 项目内相对路径、绝对路径或完整 Markdown 链接。不能仅靠固定措辞决定权威性。明确当前 Markdown 权威时，不读取或追踪无消费者的旧 JSON；来源不明且旧 JSON 存在、或声明指向其他来源时，沿真实消费者核对，不猜 schema 或把旧派生文件当当前源。
- `## 已确认待拆解` 表只记稳定 ID、事项摘要及原确认来源，不复制子任务进度或自动收录未确认想法。尚无任务清单也保留这些事项及拆解缺口。
- “进行中 / 待推进 / 受阻 / 待验证 / 验收 / 已确认待拆解”只作视图分组，状态与本端顺序仍读取原清单；同名 ID 带任务来源链接。“待推进”不代表实际输入已就绪。必要验证随实现任务时标明 `验收追踪：随实现任务`；代码交付与后续验证分开时，在同一清单按需用 `## 验收任务` 同格式表跟踪，已有报告只引用为证据。
- 缺文件、错列、未知状态、验收归属不明或 done 无证据定位须保留复核缺口。退出码 0 表示已登记来源与视图一致且无已识别缺口，1 表示缺口 / 滞后，2 表示失败；随原汇报模板说明，不把退出码当业务验收。
- 新视图带本工具生成标记；已有无标记 TODO（包括旧版生成文件）先保留并报告归属冲突，不按文件名 / 相似正文接管，不新增强制覆盖入口。写入失败或源 / 目标并发变化时保留成功更新的源和既有视图，注明滞后；只读检查不创建或改写文件。
