## 有意保留的差异

| 原文中的规则方向 | 本规范取舍与原因 |
| --- | --- |
| 魔法值、常量分组 / 复用层级、固定值域枚举 | 保留业务语义值的显式定义；数字与字符串均适用。按实际作用域复用，不机械提取算法字面量、不创建全局常量库 |
| 金额最小单位整数；同时给出 BigDecimal / DECIMAL 规则 | 交易资产精度与单位遵守契约，允许两类精确模型；不统一为分或两位小数 |
| BigDecimal 一律 compareTo | 数值比较采用 compareTo；明确比较 scale / 表示时允许 equals，集合键另核对 |
| POJO / RPC 一律包装类型、默认值 / 布尔命名统一限制 | 按 null / presence 和实际序列化映射判断，不能破坏 protobuf 等生成协议 |
| Service 接口与 Impl、类作者日期、方法长度等固定形式 | 仅在项目明确要求时遵守，不为形式新增层、重命名和机械注释 |
| toMap 总要求 merge；Arrays.asList 的修改限制 | 唯一 key 可不合并；重复 key 不静默丢数据。固定长度集合允许替换元素，区分结构变更 |
| 禁止 Executors / 自建线程；资金悲观锁；重试次数下限 | 核对实际执行器资源边界、并发原子性及安全重试；尊重框架管理和 JDK 版本，不锁定单一 API 或策略 |
| 前后端统一响应结构 / 五位错误码 | 保留项目已有契约；兼容变更独立确认，不借编码规范迁移全系统 |
| 日志级别判断、文件路径、留存等统一约定 | 按实际参数成本和已有日志设施执行；运维 / 法律要求由对应规则确认，不在编码任务套用过时常量 |
| 外键、物理删除、表必备列、SQL 数量等统一限制 | 依现有模型、约束、授权迁移与实际性能判断；不删除已有数据保护或制造迁移 |
| 业务唯一索引与查询边界 | 保留已确认业务唯一性的数据库兜底，主键已覆盖同一业务唯一性时不重复加约束；跨分片替代保障须单独有证据。单条 / 单行统计无需分页，列表和多行聚合按实际规模核对；游标续读与排序一致。这些是数据库语义和项目查询适配，不伪称手册统一豁免 |
| 统一覆盖率和单测替身建议 | 风险与项目流程优先；隔离测试、集成证据与生产路径明确分开 |
| RPC / 动态调用捕获 Throwable | 在明确隔离边界核对实际错误，不推广为通用吞错模式；finally 不能覆盖原异常 |
| 依赖坐标、起始版本和接口返回枚举的统一约定 | 保留发布可追溯、兼容与传递依赖核查；包坐标 / 已有版本 / protobuf 枚举按当前项目，不另造治理要求 |

其余新增的账户 / 租户映射、写入超时结果不明、异步事务边界、测试结果读回等属于团队场景适配，不标为“阿里强制”。

## 框架语义核对入口

- [Java 11 BigDecimal API](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/math/BigDecimal.html)：构造、compareTo / equals、scale、舍入与转换。
- [Spring 5.3 事务文档](https://docs.spring.io/spring-framework/docs/5.3.39/reference/html/data-access.html#transaction-declarative-annotations)：代理、自调用、异常、传播与管理器；是核对入口，不要求项目升级至此版本，其他版本查对应文档。
- [MyBatis 参数与映射](https://mybatis.org/mybatis-3/sqlmap-xml.html)：参数绑定、结构替换与结果映射。
- [gRPC deadline](https://grpc.io/docs/guides/deadlines/)：截止时间与传播；是否已设置需检查实际 client / interceptor / service config。
- [JDK 21 虚拟线程](https://docs.oracle.com/en/java/javase/21/core/virtual-threads.html)：仅用于解释版本条件，不授权把旧项目升级到 21。

## 团队适配边界

初版按 Maven、Spring、MyBatis、gRPC / HTTP、关系数据库和交易类精确金额服务组织。抽样仓库存在 Java 11 编译目标及测试跳过 / 失败忽略配置，因此把语言目标和实际测试结果列为核查项；这不是所有模块的统一版本声明。每次使用仍读取当前项目配置和契约，不在此固化私有服务、账户规则、金额精度或本机路径。

本规范不自动安装 PMD / 插件，不修改父 POM，不增加 CI 阻断，不要求新增审批；新增强制工具或全库治理需单独明确范围。
