# Java 编码规则

后端 Java 实现与代码审查直接读取本公共规范，不需要单独调用命令。按 [来源与适配](java-coding-sources.md) 识别手册来源、团队适配和条件规则；已有交付入口沿用自己的范围和阶段门。

## 适用与取舍

- 先读取目标模块的仓库指令、构建及父配置、已有格式 / 静态检查配置、相关契约与相邻实现；按实际语言目标和框架版本使用，不用本机 JDK 推断项目目标。
- “必须”用于适用场景中的正确性、边界和兼容约束，“建议”可按上下文取舍。格式 / 结构服从项目已确认约定，业务语义服从已确认契约；不能以历史习惯豁免已证实的越权、资损或数据损坏风险。
- 按当前改动选择相关章节，不全库扫描或顺手重构，不修改生成产物来消除告警。审查要求只读时不修代码；拿不准的记录证据缺口与待核查问题，风格建议不冒充已证实缺陷，也不新增批准流程。

## 基础：命名、格式、对象与集合

- **必须**使用能表达业务含义的名称，避免新引入晦涩缩写、拼音混搭和易混淆标识符；类名 UpperCamelCase、成员 / 方法 lowerCamelCase、常量 UPPER_SNAKE_CASE、包名小写。接口 / 序列化 / 数据库既有名称不得仅为风格修改；布尔属性要核对真实 getter、Lombok 与序列化映射，不能机械去掉 `is`。
- **建议**无明确配置时采用 UTF-8、LF、4 空格缩进及约 120 字符行宽，控制语句加大括号，覆盖方法加 `@Override`。超长方法或深层嵌套先判断职责与可读性，不按固定行数自动拆分，不为消除告警全量重排文件。
- **必须**保护已发布方法、DTO、序列化字段、枚举值与错误码的兼容性；弃用应有可用替代与迁移依据。是否抽 Service 接口、增加 Impl 或引入设计模式，取决于现有结构和变化需求，不强制增加空抽象。
- **必须**区分“未提供”“未知”“零”和“空集合”；不能用默认 0 / false / 空对象掩盖查询失败或状态缺失。包装类型与 primitive 根据可空语义、数据库映射和协议选择，不统一改造所有 POJO / protobuf 字段。
- **必须**对对象值使用符合语义的相等判断，防止包装数值的引用比较；覆盖 `equals` 时保证 `hashCode` 一致，作为 key 的字段不应在入 Map / Set 后改变。比较器避免用整数相减造成溢出。
- **必须**保持比较器的互反性、传递性及相等情况下的一致性；不能用只返回 `1` / `-1` 的比较器遗漏相等情形。数值转换、乘加与计数按实际范围检查溢出，不以强转或截断掩盖超范围数据。
- **必须**理解集合的可变性、视图、泛型和顺序。`Arrays.asList` 不能改变长度但允许 `set`；`subList` 与父列表共享视图。遍历时结构变更使用受支持方式，不把所有集合修改一概判错。
- **必须**按具体集合处理 null、元素类型与数组转换；`ConcurrentHashMap` 不接受 null key / value，无参 `toArray()` 的结果不能直接强转为 `String[]` 等具体数组。保留泛型约束，不以未检查的强转代替来源验证。
- **必须**处理 `Collectors.toMap` 的实际重复 key / null 值语义：唯一性确有保证时可用无 merge 版本；可能重复时决定拒绝、聚合或合并，不能为避免异常随意保留第一条而丢业务数据。原地修改与并行流需检查副作用、共享状态和顺序。
- **必须**核对拷贝的深浅和可变字段别名关系；`clone`、BeanUtils 等属性复制不保证深拷贝，不能让修改副本意外改变原业务对象。序列化升级核对实际格式与兼容规则，Java Serializable 的兼容性不能仅凭“只加了字段”认定，也不能无依据改 `serialVersionUID`；不手改生成协议。
- **建议**按职责收紧成员可见性，保持枚举业务属性私有且不可变；构造、getter / setter 中避免隐藏远程调用、持久化与意外副作用。无需框架注入的纯初始化不机械搬到 `init`，也不为规范批量改造历史类型。
- **建议**注释解释契约、单位、边界、不变量和取舍；重要公开接口补充 Javadoc。清晰代码不补机械翻译注释，不强制作者 / 日期模板；过期注释随相关代码更新。

## 常量与魔法值

- **必须**避免直接散落未经语义定义的业务值，包括状态数字、类型码、缓存 key / 前缀、协议标记、超时和业务阈值；优先复用已有枚举、常量、key 构造方法或配置，不能仅靠注释解释后继续到处复制字面量。状态 / 类型是固定值域时可用枚举表达，但保持已确认的数据库值和对外协议值，不用 `ordinal()` 代替业务编码。
- **必须**用名称表达用途及必要单位，例如 `ORDER_QUERY_TIMEOUT_MILLIS`；`NUMBER_THREE` 或 `STATUS_3` 只是把数字换个位置，不能代替业务含义。超时可使用项目支持的 `Duration` 等类型；可运营调整的参数沿用现有配置，不把规则值随意固化到代码。
- **建议**按最小合理作用域维护常量，类内常量优先 `private static final`，共用值放到对应领域；同一语义复用同一定义，不因数值相同就合并不同业务概念，不新建囊括所有常量的全局类或公共库。
- 普通计数起点、索引步长、数学运算等上下文清楚的字面量，不为形式机械提取。`0` / `1` 不是豁免名单：表示业务状态时仍需语义定义；显式枚举编码或常量 / 配置的定义位置出现数字，本身不构成魔法值。是否存在实际缺陷及严重度按业务影响判断，不按数字数量评分。

## 控制流与空值

- **必须**在自动拆箱、三目表达式、级联调用、外部返回及集合元素读取时核对可空语义；集合非空不保证元素非空，三目表达式的类型对齐也可能触发拆箱。已由契约建立非空不变量时不逐行重复防御，也不把未知金额 / 状态静默默认成零。
- **必须**对 `switch` 的空输入、未知状态、遗漏分支及非预期贯穿有明确处理；传统语句分支按实际需要终止，故意贯穿写清理由。未知订单 / 资金状态不能落入成功路径；语言版本允许且编译器已保证穷尽的表达式，不机械添加无意义分支。
- **建议**用卫语句和有业务名称的条件简化复杂分支，避免将赋值和隐藏副作用混入判断；不按固定嵌套层数强行套设计模式。并发阈值判断核对是否可能跳过等值点，改成区间判断也不能替代原子性保护。
- **建议**固定且高频的正则复用预编译结果；动态规则按实际来源和生命周期处理，不强制所有 `Pattern.compile` 移成 static。对不可信规则 / 文本控制匹配成本；字符串切分要核对尾部空项、实际长度及索引，不能假定 `split` 保留所有字段。

## 金额与时间（涉及相关字段或计算时）

- **必须**遵守契约确认的币种、账户、精度、单位、正负号、余额口径、费率和舍入阶段。精确金额可使用 `BigDecimal` / 数据库 DECIMAL，或已定义最小单位的整数；禁止引入 float / double 计算精确资金。不全局统一成“分”、两位小数或某个舍入模式。
- **必须**从精确十进制文本或已定义整数单位构造金额，避免 `new BigDecimal(double)`；`BigDecimal.valueOf(double)` 也不能恢复上游已经丢失的精度。做转换时核对范围、溢出和截断，不能无条件 `longValue()`。
- **必须**按业务选择比较语义：数值相等用 `compareTo(...) == 0`；`equals` 同时比较 scale，明确要求表示形式相同时允许使用。Map / Set 采用哪种相等语义也要一致。除法按契约处理精度和舍入，可能精确整除的调用不机械添加舍入；不允许舍入的场景应明确拒绝不可表示结果。
- **必须**将余额 / 账户 / 币种 / 租户映射到真实来源；`available`、`total`、权益等不可互换。空值、超时和失败不能默认变为零余额或结算成功；字段语义缺失先补证，不根据名称猜公式。
- **必须**明确时间字段的时区、秒 / 毫秒单位、业务日期及区间边界；涉及跨年、闰年、夏令时或过期判断时覆盖相关边界。普通公历年与周年格式不要混用；优先 `java.time`，不共享未同步的 `SimpleDateFormat`。
- **建议**需要可控当前时间的业务使用可注入 `Clock` 或已有时钟抽象；比较耗时使用适合时长测量的时间源，不假设墙钟单调。遵循既有存储 / API 时间格式，不以规范之名迁移所有历史字段。

## 并发与资源（涉及共享状态或异步工作时）

- **必须**识别线程共享状态、复合读改写和可见性；`volatile`、线程安全容器或同一 Pod 本身不保证整个业务操作原子性 / 有序性。不能仅凭 `ConcurrentHashMap` 或同一 Kafka key 就声称业务安全。
- **必须**让并发量、排队、拒绝、超时和关闭行为可控。优先复用受管理执行器；自建平台线程池要明确容量、线程名、任务失败处理和生命周期，不能在请求路径无界创建线程或任务。框架执行器、调度器、ForkJoin 或支持版本的虚拟线程按其语义核查，不一律改写成 `ThreadPoolExecutor`。
- **必须**观察异步任务失败；`Future` / `CompletableFuture` 不能提交后丢失失败语义。耗时等待应有适用的超时 / 取消策略；处理中断时按方法契约传播，或恢复中断标志并停止相应工作，不能捕获后继续当成功执行。
- **必须**核对定时任务抛异常后是否停止后续调度，以及并行子任务异常 / 提前退出时等待条件能否完成；使用 `CountDownLatch` 时对相应执行路径可靠地 `countDown`，不能只在成功分支递减。是否允许继续调度按任务失败语义处理，不以捕获异常掩盖失败。
- **必须**按实际获得的所有权释放锁；`tryLock` 失败不解锁。多锁顺序一致，临界区避免无必要的远程等待。分布式锁需核对过期、续租和释放归属，不能把持有本地锁当跨实例互斥。
- **必须**正确清理自有 ThreadLocal / MDC / 身份上下文并处理上下文传播；嵌套调用需恢复先前值，不删除不归当前作用域管理的上下文。
- **必须**对重复提交、消息重投和并发写入定义结果与原子边界；“先查后插”、按钮禁用或内存标记不等于跨实例幂等。唯一约束、状态条件更新、版本或锁按业务选用，不要求金额场景一律悲观锁，也不固定重试至少三次。
- **必须**只对可安全重试的操作重试，限制总时间和次数并考虑退避；写操作超时可能已成功，需按已有幂等键 / 状态查询处理结果不明，不盲目再次扣款、下单或发送。资源按所有权关闭，自有流优先 try-with-resources；不要关闭框架共享连接池或 client。

## Spring 事务与持久化（涉及数据库时）

- **必须**检查事务管理器、数据源、代理调用路径、传播与回滚语义。默认代理模式下自调用不能触发被调用方法额外的事务拦截；若外层已有事务则仍可能参与外层，不能仅凭自调用就断言完全无事务。按项目版本核实方法可见性限制，不套用另一版本的规则。
- **必须**明确业务失败是否回滚；捕获后返回成功、checked exception、异步切线程、错误数据源或 `REQUIRES_NEW` 可能改变结果。`rollbackFor = Exception.class` 不是必须统一添加的装饰，应根据需要回滚的异常与配置验证。
- **必须**承认本地事务不自动覆盖远程 HTTP / gRPC、消息和缓存；有一致性要求时使用已有可靠机制或提出最小方案并说明失败路径。不为每个简单操作强加分布式事务、Outbox 或补偿平台；依赖的事务提交后回调不等于持久可靠消息。
- **必须**将实体 / Mapper / XML 与权威 DDL 的列名、类型、精度、空值、默认值、索引及状态语义对齐。更新 / 删除必须有业务所需的范围约束；空条件、空集合不能移除保护性 WHERE。批量写入核对部分失败与影响行数，条件更新返回 0 时不能默认成功。
- **必须**对已确认具有唯一语义的业务键以数据库唯一约束兜底，核对真实唯一范围（如租户与业务单号组合）、适用记录与空值语义。主键（包括自增主键）已完整覆盖所需业务唯一性时，已有主键约束即可，不重复添加同键的 UNIQUE；无关的代理主键、普通索引、“先查后插”或单进程锁不能替代另一业务键的唯一约束。标识唯一不等于重复请求已幂等，仍核对相关写入路径和重复冲突处理；跨分片等不能直接由单库约束覆盖时，须有已确认、能覆盖相关写入路径的原子性替代保障及验证依据，不能仅写“有锁”。唯一范围或保障方式未确认时补证，不根据字段名猜键，也不因此自动改造历史表或执行迁移。
- **必须**按实际意图选择更新字段，不把带默认值或旧值的整个 POJO 无差别覆盖数据库；创建时间、状态、审计字段及并发版本遵循既有规则。SQL 聚合明确空集 / NULL 语义，`COUNT(*)`、`COUNT(column)` 与 `SUM` 不能混同；是否把聚合 NULL 转零由业务契约决定，不统一吞成零值。
- **必须**对 SQL 值参数绑定；动态表名、列名、排序等结构只能来自受控映射 / 允许集，不直接拼用户输入。`${}` 不是单凭语法即成立的漏洞，需检查真实来源与约束；`#{}` 也不能替代身份与资源授权。
- **必须**按查询返回范围和消费方式控制多行列表 / 批处理规模，可采用分页、游标或有界分批等适合现有场景的方式。需要稳定分页 / 遍历时使用确定排序并处理同值排序键；按主键 / 已证唯一键取单条、确定只返回单行的聚合统计，不强加排序或分页。`LIMIT 1` 本身不证明业务唯一；`GROUP BY` 等可能返回多行的聚合仍按实际规模核对边界，不能把所有聚合一律豁免。检查实际 N+1、无界加载、索引和查询条件；性能结论依据表规模、执行计划和调用路径，不能只凭 `JOIN` 数量、`COUNT(1)` 或 `SELECT *` 字样断言故障。
- **必须**让游标续读条件与实际排序一致：游标及已有上下文须足以恢复续读的排序位置，比较方向、同值排序键、适用的空值语义及边界处理遵守同一规则。按 `created_at DESC, id DESC` 排序时，不能仅用 `id < lastId` 续读；仅按唯一 id 排序时，匹配方向和边界的 id 游标可以成立，不强制改成复合游标或另建协议。按既有分页契约验证静态遍历的完整性与边界，避免漏读或意外重复；确定排序本身不保证并发写入下跨页快照一致，是否需要快照按既有业务契约判断。
- **建议**明确所需列与映射，复用可靠的自动映射时不强制每次写 resultMap。已有外键、物理删除和主键策略遵循业务与迁移约束，不自动改软删除、不移除约束。新增 / 修改 schema 按授权及迁移流程执行，不以规范检查代替执行许可。

## 接口、异常、日志与安全（涉及边界时）

- **必须**在信任边界验证输入类型、范围、长度、枚举及数量；使用可信身份核对资源归属，租户 / 用户 / 账户不能仅信任请求字段。内部已建立不变量的私有方法不强制逐层重复校验。
- **必须**保持已确认 HTTP / gRPC / JSON / protobuf 契约、字段缺省语义、状态码与错误映射；不用手册的五位错误码或单一响应结构覆盖历史协议。新增 JS 消费的大整数及精确金额要明确可保真的序列化约定，既有契约变更需兼容方案，不能悄悄把全部 Long 改字符串。
- **必须**为外部调用采用适用的超时 / gRPC deadline 与失败语义，优先使用已配置的 client / interceptor；缺少逐行 `withDeadlineAfter` 不等于未设超时。只读失败与写入结果不明分别处理，重试沿用并发段的约束。
- **必须**避免用异常表示普通分支，不吞异常或把失败伪装成空成功；保留 cause，边界按项目规则转换，面向用户不暴露堆栈 / SQL / 凭据。任务隔离边界允许捕获广义异常，但要处理失败并保证继续执行的语义合理，不机械禁止所有 `catch(Exception)`。
- **必须**避免在 `finally` 中 `return` 或抛出掩盖原始结果 / 异常的新错误；清理失败要保留原始失败信息。捕获到的异常类型须覆盖真正需要处理的失败；不为照搬 RPC 示例在所有调用处捕获 `Throwable` 并当成功继续，依赖装载错误应结合故障隔离边界明确处理。
- **必须**使用项目日志框架与参数占位符，保留定位所需的脱敏业务 ID / trace 和失败上下文；避免重复多层堆栈及无界 payload。密码、token、API secret、签名原文中的秘密、OTP 等不能写入日志 / fixture / 提交；不要用自动 `toString` 或 Lombok `@Data` 把敏感字段带入日志。
- **建议**昂贵的日志参数求值用适用级别判断或已有惰性接口；简单占位参数不强制每行加 `isInfoEnabled()`。业务拒绝与系统故障按已有级别区分，不新增高基数指标标签或大量循环日志；日志留存、路径与采集由项目运维约定管理。
- **必须**对本次涉及的上传、重定向、外部 URL、命令执行、反序列化和浏览器输出核对相应安全边界；不要因规范检查自动扩成全站安全扫描。CSRF 是否适用取决于浏览器自动携带凭据等认证方式；凭据沿用已有安全配置 / secret 管理，不新建自制加密体系。
- **必须**对短信、邮件、下单和支付等本次涉及的有成本操作，按已确认策略核对防重放、重复请求与滥用限制；不自行编造次数 / 阈值。弱依赖失败只可按已确认降级语义处理，不能将鉴权、资金校验等关键失败降级为成功。

## 验证（所有模式按风险采用）

- **必须**遵守当前模块的语言目标和依赖版本，不默认引入 record、虚拟线程、Spring 6 / Jakarta 或升级公共库。依赖冲突检查实际解析 / 打包来源，不能从一个 jar 的缺失方法推断必须升级全部服务。
- **必须**使正式发布的依赖版本与制品可追溯，不未经说明引入 SNAPSHOT、动态版本或覆盖已发布制品；升级依赖时检查传递依赖仲裁差异，而不只看目标库版本。沿用已有版本管理与 BOM，不擅自改 Maven 坐标、统一所有服务版本或为清理冲突升级无关依赖。
- **必须**对相关缺陷或高风险改动补充能验证预期结果的用例：按适用性覆盖正常、边界、非法输入、权限、重复、并发、回滚和副作用；不为无行为变化的局部格式整理机械新增测试。用例应自动断言、独立、可重复，异步断言避免仅用固定 sleep，数据与凭据用合成材料。
- **必须**区分单元隔离与真实集成。测试替身可以验证隔离逻辑，不能作为真实 SQL、事务代理、下游协议或端到端完成的证明。若当前工作流限制测试替身，沿用限制，不自行放宽；生产路径不得用 mock / fake 代替真实能力。
- **必须**检查 Maven / Gradle 是否跳过测试或忽略失败，并读取本次 Surefire / Failsafe / 对应报告的执行数、失败数、跳过数和选择范围；旧报告、编译成功或退出码 0 不等于测试通过。按当前项目命令选择必要覆盖，不为达成固定覆盖率补无效断言。
- **必须**报告实际验证命令、结果和缺口；环境缺失、测试未跑或只做静态走查时明确说明。不修改生产数据、不发送真实订单或资金请求来验证编码规范。
