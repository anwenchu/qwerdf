# 产物生命周期与上下文恢复

各阶段产物路径及维护职责以 [阶段产物表](product-delivery-flow.md#1-交付链路) 为准；本文件统一规模、更新、证据与续作规则，不新增业务阶段、任务状态或执行权限。

## 工作规则

- 默认以需求、技术方案、任务清单三份主文档为工作入口：需求与验收在 `product/prd.md`，设计 / 数据 / 真实输入 / 风险在 `tech/tech-plan.md`，状态与简短实现 / 验证 / 续作记录在 `tech/task-slices.md`。旧分文件或确需独立消费的契约、UI、SQL、报告引用唯一来源；不是缺哪个旧文件名就补建哪个。
- 先识别已授权阶段、任务范围及本轮受影响的当前产物。只有进入该阶段才维护对应文档，局部修订只更新相关部分，不重建其他阶段的整套材料，也不预生成未进入阶段的空文档。模板是结构参考，不是每轮新建文件的清单。
- 当前文档在既有 canonical path 原位更新；同一事实只在其权威位置维护，其他文档引用。已有 JSON / Markdown 任务源按共享任务规则处理，不因压缩或恢复上下文另建一套状态。历史说明不能覆盖当前已确认规则，已有证据也不能无声改写。
- 展开需求、蓝图或技术方案正文前，先在当前需求 / 方案总览评估业务范围、交付单元、必要产物的数量和预期正文总量，不另建规模报告。若包含多个独立业务结果，或预计产物数量 / 单文档长度已难以定向审阅、实现和交接，先按 [规模预算与任务拆分](#规模预算与任务拆分) 收敛需求并拆分交付单元，再逐个展开；不能等生成大量文件或超长正文后只记一句风险继续追加。
- 单主题说明正文约 300 行或 20KB、单任务新增说明正文总量约 20KB 作为默认复核线；接近或预计超出时先去重、收敛，确需详情则按稳定业务主题拆分并保留唯一入口。还须检查整个需求的文件数量、累计正文与重复比例，不能靠拆很多小任务 / 小文件或移入 evidence 绕过；不把每个子任务复制一整套阶段产物。不可再分的必要契约可有有界例外，不能以“复杂”为由持续膨胀成巨量文档或万行单篇。
- 正式文档只留当前结论、必要依据和相关引用；实现记录按任务更新简短进展 / 检查 / 阻断，不为每条命令追加完整复盘，不在多份日志粘贴相同背景和输出。变更路径优先引用 Git diff，简短结果与必要注意事项写回原任务；已有专用记录只引用，不再自动生成日志、路径表、备注和验收四份副本。正式报告保留相应验证证据。
- 证据只保存支持当前结论的必要增量及定位。已有可靠版本 / 原文件可追溯时用引用、摘要和必要差异，不每轮复制全部文档或创建递归 before/after 快照；证据目录本身不成为再次快照的输入。不可恢复的未跟踪内容确需保护时，只对受影响内容留最小基线并说明用途，不强迫提交或假称忽略文件已有版本历史。必要安全备份和验收证据不因去重省略。
- 复用已有约定的续作入口；没有时在任务清单的“当前续作”小节记录，设计阶段尚无任务清单就在当前方案 / 需求末尾记下一动作，不为续作新建 README、CURRENT 或状态文件。在阶段交接、当前任务 / 关键未决变化或中断交接时更新导航，不为普通命令反复生成摘要。续作小节建议约 60 行以内，只记目标 / 范围、当前阶段、权威任务源、有效材料与未决引用、下一动作及证据入口，不复制业务规则或任务状态表。并行工作分别引用各端记录，不用一个“当前任务”覆盖他人进展；不得把凭证写入入口。
- 续作先读简短入口，再核对当前权威任务、相关有效设计、实现及必要依赖 / 验证记录；确认摘要未过期后继续获准工作。仅按链接读取相关片段，不递归读取全部证据或无变化的长日志。入口缺失不自动阻断：从用户指定范围及已知当前产物重建最小上下文，不能据缺入口猜业务事实；文件仍在不代表已被本轮读取或验证。
- 文档或日志接近复核线时收敛当前摘要与稳定主题索引；已闭合历史如需整理，在授权范围保留可回查路径和证据关联，不每轮新增归档目录。未授权不删除、搬迁或清理旧文件；明确禁止写文件的只读检查只在回复中给摘要。上下文恢复不解除任务阻断、设计缺口或外部操作限制，也不把原有记录存在当作当前验证通过。

## 规模预算与任务拆分

- 先按用户场景与可独立验收的业务结果拆交付单元，再拆每个单元的实现任务；必要工程准备随实际归属安排。不按类 / 方法 / helper、固定工时或文件数量机械拆分，不将整条含多个独立结果的大链路塞成长期无法验收的一项。
- 复用当前 PRD / 技术总览中的一段索引，写清各单元的范围、预期结果、验收引用及必要文档影响；共用身份、权限、金额语义、契约等约束在一处维护，单元只引用差异。纯组织拆分可在已授权范围直接做；若改变业务规则、原交付范围或正式分期，才需要相应确认。拆分不自动放行未完成的技术设计，也不缩小原本要求整体完成的交接范围。
- 每个单元只展开当前阶段实际需要的产物，优先更新已有文件。项目级入口保留短总览与稳定主题索引，详情各有唯一位置；任务表保留简短业务动作、完成标准 / 证据引用与状态，不粘贴完整设计或日志。不得为每个任务、方法、finding 或会话各建一套 PRD / 设计 / 报告目录，也不在总览和详情复制正文。拆分只移出长说明，主索引保留稳定需求 / 验收编号、关联及简短可观察结果，再引用唯一详情；不把关键映射挪走后让检查误判不存在。工具未覆盖的部分人工核对，真实缺失、冲突或断链仍阻断，不伪报机械通过。
- 数值是复核触发条件，不是自动 FAIL、整个仓库配额或截断文档的依据；已有合理预算可沿用。预算计算说明正文，不混入未改的既有长文、源码或必要原始截图，但须看整个需求的累计产物。完整协议等确需超出时，说明必要性、主题边界与读取入口，不静默反复抬高预算；必要权限、异常、事务 / 一致性和验证要求不因压缩而省略。

## 证据与历史边界

- 记录命令 / 方式、范围 / 版本、结果、必要失败片段和原始证据位置；完整输出只有确需复现 / 审计才保留。工具的临时下载、缓存和构建二进制优先留在既有工具目录，文档引用版本、校验值与定位，不默认拷贝到证据树。
- 修改前保护只覆盖本轮受影响、无法从既有可靠记录恢复的内容；不能为了“保险”复制整个产物目录。正式版本归档与必要数据库 / 发布备份按原要求保留，这些不能用文档摘要替代。
- 截图及外部证据以被检查对象 / 版本 / 状态定位；对象未变且证据仍适用时复用引用，变更后按原质量要求重验受影响范围。截图数量不能按正文预算裁减，旧图不能冒充新状态；失败与结果未知也须保留必要证据。

## 简短续作入口

复用已约定入口或任务清单的“当前续作”小节，保留无关内容；只在获准维护产物时更新。链接需指向真实有效的当前材料，任务状态和业务规则仍回其权威源核对。下面是导航内容示意，不要求新增另一份任务 / 进度文件。

```text
目标与范围：<本轮约定及明确不做的事>
阶段与任务来源：<当前阶段；权威任务路径；并行工作各自入口>
有效材料：<当前需求 / 设计 / 契约的路径与必要章节，不复制全文>
未决与限制：<问题 / 阻断记录及授权边界的引用>
下一动作：<任务 ID 或必要补证；继续前需核对的条件>
证据入口：<相关实现记录、验证结果及原始证据位置>
```
