# UI Quality Checklist

用于蓝图、Figma、前端与 UI Review。按本次产品任务、平台和状态选取检查项；严重性、三层审查适用性及不能交付条件只在 [UI Review Rules](ui-review-rules.md) 维护。不适用项说明理由，未验证项不得填成通过。

## 1. 任务与视觉层级

- 首屏可识别主体、当前任务、状态与主操作；危险操作和普通操作不混淆。
- 管理后台 / SaaS / CRM 优先扫描、比较与处理效率；只有需求明确时引入营销 hero。品牌风格可变化，不能牺牲关键内容与动作。
- 标题、分组、label/value、数值、辅助说明和操作层级稳定；同类组件遵循同一语义与布局策略，批准 variant 和内容自适应高度可以不同。

## 2. 布局、间距与内容边界

- 文本不重叠，关键内容与按钮不被固定栏、浮层或容器无意义裁切；检查长中文、长英文、金额、状态及按钮文案。
- 页面无横向溢出；移动表格按任务选择卡片、摘要、分组或有提示的局部横向滚动，需要列间比较时可保留表格。完整内容与关键操作仍能获取，不用隐藏关键金额或操作来消除溢出。
- 字体、spacing scale、容器宽度、行高、padding 与操作位置符合 MASTER / Page Overrides，不靠任意缩小字体掩盖布局破损。
- 右侧安全边距、移动端侧距、行内操作间距优先用已有系统。没有约束时可从侧距 16px、行内间距 12-16px 起步；这是设计起点，不是截图判定 P1 的固定阈值。检查实际可读性、点击目标、误触与安全区避让。
- 按产品实际断点检查窄屏、布局变化处与宽屏，不强制所有页面同一组像素值。hover、字体加载、异步内容、错误反馈出现后不能造成关键内容遮挡或不可控跳动。

## 3. Token、字体与图标

- 使用设计系统的语义 token 及批准组件变体；值、别名和来源在 MASTER 统一维护，页面仅引用或记录必要差异。
- 同语义字体层级一致；中英文、数字、金额、百分比、badge 与按钮检查基线和行高。不同响应式层级不强制同字号。
- 状态不只靠颜色区分；图标风格和动作语义清楚，品牌或内容中的 emoji 不等于结构性图标缺陷。
- 风格候选按产品任务、品牌、密度和平台选择；不把紫色、渐变或圆角列成全局禁用项，不让检索建议覆盖已确认设计。

## 4. 适用的状态与交互

| 条件 | 检查 |
| --- | --- |
| 有异步加载 | loading 反馈与布局稳定性；必要错误与重试路径。 |
| 可能无数据 | empty 的原因、下一步动作或无需动作的说明。 |
| 存在权限差异 | permission 的可见性与返回 / 申请路径，不能凭默认截图验证权限正确。 |
| 有写操作 | saving / submitting、防重复操作、成功 / 失败反馈及输入保留。 |
| 有键盘 / 触控输入 | focus、可达性、控件名称、点击目标与适合平台的交互；触屏不以 hover 为唯一入口。 |

静态公开页面可仅覆盖 default；共享组件的通用状态可维护一次，页面说明引用与差异。不要求重复制作所有状态页，也不能以不适用略过实际关键失败路径。

## 5. 表单、列表、详情与图表

- 表单按业务分组，必填、格式、边界和跨字段规则来自需求；错误可定位、可恢复，危险操作清楚说明后果。
- 列表 / 表格先明确主识别信息、状态、关键指标与操作；适用的筛选、排序、分页、批量操作有反馈，不为了套模板增加功能。
- 金额、百分比、单位、时间和枚举格式一致；详情的摘要、关联信息和操作有稳定阅读顺序。
- 图表服务具体问题，单位、范围、图例、异常与缺失数据可解释，不让视觉层级误导判断。

## 6. 可访问性

- 按平台目标检查键盘、可见焦点、语义名称、输入 label、非颜色唯一表达、对比度与 reduced motion。
- 需要运行证据的项目不能靠静态截图宣称合规；目标标准、测量方式和未验证项如实记录。

## 7. 独立 UI Review 与 Figma 交付前截图 QA

- `ui/ui-review-report.md` 记录机器扫描、视觉扫描、模板扫描的已检查 / 不适用 / 未验证结果；检查证据可比较条件和同类问题扫描范围，不重复抄检查清单。
- Figma 交付记录本次目标 frame / 断点的截图 QA 与待确认项；实际页面验收记录在 `tech/frontend/frontend-acceptance.md`，组件样例不替代真实宿主页面验证。
- 修复记录关联具体 finding、更新后的截图与复查范围。交接判断统一读取共享规则，不把文字自述当修复证明。
