# 技术设计依据与范围规则

用于 `$pd-plan` 的设计交接，以及 `$pd-fe`、`$pd-be`、`$pd-review` 对方案的核对。模板只记录结论与引用，不在各入口重复维护规则。

## 1. 先限定本轮问题和交付范围

- 从用户当前要求、已确认 PRD / 验收和已有决定提取业务目标、本期链路、涉及对象、改动边界和非目标。已有稳定需求编号沿用，没有编号可引用原文位置，不为填表强制重编号。
- 每项拟修改的模块、依赖、接口、表或任务，都应能关联已确认需求，或解释它为何是完成该需求不可缺少的技术前置。发现现状缺陷不等于获准修复它；“顺手兼容全系统”“统一所有旧接口”不能代替本期必要性说明。
- 区分**改动范围**和**只读影响核查范围**。可沿本轮调用链、共享读写约束、直接调用方和实际依赖做有理由的核查，写明要回答的问题及何时停止；不因共享一张表、同一字段或同一个组织概念，就把所有相关业务加入本期。
- 发现范围外问题时记录位置、影响依据及是否已证实关联本期；一般建议单列，不进入本期方案承诺、SQL 或 task slices。确实会破坏本期链路或验收时，说明最小必要变更和不做的后果；已有授权沿用，尚未授权的范围变化先确认，不扩大到无关业务改造。

## 2. 关键技术结论要能追溯

- 区分源码 / 契约事实、设计提案和未确认项。定位使用仓库 / 模块、路径、符号与必要行号；依赖版本、分支或配置差异会改变结论时记录对应版本和适用条件。没有取得的证据明确写缺失，不能编造文件、类、接口或行号。
- 复用关键接口时，说明调用方、提供服务及协议全名：例如 HTTP method + path、gRPC service/method 或消息 topic / 事件类型；追到可信契约和已有调用 / 绑定证据，能取得时核对提供方实现。本次首次接入时可明确拟新增调用位置，不强求已有调用代码。外部闭源服务可引用相应版本的官方契约、可用 client / 配置和验证证据，不强求不可取得的源码。
- 写清业务身份 / 账户 / 租户等关键参数从哪里取得、如何映射到请求，消费返回的哪个字段、其口径 / 单位 / 状态语义，以及权限、前置校验、执行顺序、异常 / 空值与恢复路径。按本轮风险覆盖幂等、并发、事务和副作用，不用“调用资产服务”“查询用户”“复用原接口”代替接入设计。
- 源码声明、依赖可见性、实际装载和运行可用性是不同证据。涉及同名类、多个依赖包、路由 / 开关或环境配置时，核对本模块实际依赖版本、装配 / 调用配置及可取得的验证；只查一个包不能断言必须升级依赖或修改公共库。决定性装载证据缺失时保留条件结论，不拿猜测补全。
- 新增接口、类、表或字段可作为明确的**拟新增设计**，说明归属、契约、实现任务和验证方式；不因尚未实现就否定设计，也不得把拟新增能力说成现有可用能力。证据定位集中在相关设计段落或索引，其余产物引用，不复制多份易漂移的事实表。

## 3. 交付应足以让实现者执行

- 对本轮关键链路写清入口到依赖再到结果的步骤，以及复用位置、拟修改 / 新增位置、关键数据映射、失败处理和验证信号。实现者不应再猜“调用哪个服务哪个方法”“账户 ID 从哪里来”“返回字段如何用于业务判断”。简单局部修改说明受影响步骤即可，不要求为每个辅助方法补完整调用链。
- 决定可行性、权限、金额语义、共享契约或验收的未知项未解决时，只能报告草案 / 受影响部分待补 / 阻断，不能仅凭文件齐全称设计完成，也不能把相关 `contract` slice 标为 `done`。说明缺口、影响范围、所需证据和下一步；可以继续独立部分的设计核查，不把局部未知无限扩大成全项目停工；正式实现交接仍须满足既有契约和依赖 gate。
- 清楚定义且无决定性未决项的新设计可以交接，待实现的代码本身不是设计缺口。已确认的源码设计也不等于已部署 / 已联调；环境就绪状态仍只在 `tech/dependency-readiness.md` 按适用 slice 维护，真实环境验证留给对应阶段，不能伪报通过。
- 交接前用读者视角沿本期验收走查：技术接入是否具体、有依据，任务是否都服务本期，未决项是否暴露，开发者能否据此实现并验证。自由文本的真实性、因果关系和范围必要性由审阅判断，不用标题齐全、关键词命中或未经执行的脚本输出替代。

## 4. 实现与审查的回退

- 实现阶段若关键现有能力、参数来源或字段语义仍需猜测，按契约 / 设计缺口回 `$pd-plan` 补证，不由实现者静默发明接入或扩大任务。契约清楚但实现不符时仍沿用既有 `implementation-defect` 修复路线。
- 审查分别核对“引用是否支持结论”和“改动为何属于本期”。证据不足标未确认，已证实偏离范围或关键设计不可执行时按真实影响分级；相关建议不能自动升级为新增需求、依赖升级、迁移或全系统整治任务。
