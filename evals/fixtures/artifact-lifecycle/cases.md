# 产物生命周期与上下文恢复回归

按 [共享生命周期规则](../../../skills/qwerdf-common/artifact-lifecycle.md) 和 [阶段产物表](../../../skills/qwerdf-common/product-delivery-flow.md#1-交付链路) 人工评审实际产物与读写范围。以下均为通用合成场景，不授权清理已有项目、生成真实备份或写入外部系统，也不是关键词评分器。自动检查只证明结构 / 引用有效，不证明模型执行这些决策。

| 用例 | 输入 / 变化 | 应有结果 | 应拒绝的结果 |
| --- | --- | --- | --- |
| L1 阶段归属与局部修订 | 用户只授权局部需求修订；当前需求与验收文件已存在，尚未进入设计或开发 | 原位更新受影响的需求 / 验收，引用其他当前材料；不补造所有阶段文档 | 因模板目录列有很多文件就生成整套工程 / 发布材料；为每轮修改新建带日期的完整副本 |
| L2 条件性产物 | 一次联调没有契约差异；另一次出现已证实契约差异；某次设计已选定方向不需探索 | 前者维护当前计划与报告，后者按原路由补差异 / 修订；已有方向不补造候选记录。未适用文件可说明不适用 | 每次都建空差异 / 修订文件；为齐全补三套候选；反过来省略确实需要的契约修订或正式 handoff |
| L3 大任务先拆 | 计划的一项工作包含多个独立业务结果，预计新增说明超过复核线，即使分到多份文件总量仍大 | 展开正文前先在项目索引列独立任务目录、范围、完成条件与共用引用，各任务再展开当前阶段材料及实现切片 | 所有任务挤进一个可写状态总表；每个 helper 新建目录；未经确认缩小原交接范围 |
| L4 完整复杂契约 | 单个不可再分的必要契约含适用安全 / 兼容要求，正文超过默认复核线；项目已有合理的不同预算 | 先复核粒度，说明例外与主题边界，保留总览和唯一详情、按需读取；可以沿用项目预算，完整性不因大小失败 | 以行数自动 FAIL；截掉权限 / 异常字段来通过；把必要原子约束拆散；反过来静默无限抬高预算 |
| L5 当前记录与长日志 | 同一任务多次检查，已有实现记录、路径清单和 dev-notes，命令输出大部分重复 | 更新原任务的当前进展 / 检查 / 阻断，各文档只记录本职信息；必要原始输出按引用定位 | 每次往多份日志粘贴相同背景、全量 diff 和输出；每条命令新建复盘文档；用简短为由删掉未解决阻断和验证缺口 |
| L6 增量保护与必要备份 | 输入一受影响文档有可靠版本记录；输入二尚未跟踪且不可恢复；输入三原流程明确要求真实安全备份 | 一引用版本和必要差异；二只为受影响内容留最小基线并说明用途；三保留原备份要求及证据，不混作普通文档去重 | 每轮复制整目录及其中的历史 evidence；假称未跟踪文件可从版本历史找回；为方便回滚擅自提交；以减文件为由省略必要安全备份 |
| L7 图片与构建产物 | 目标画面变更后需新截图，其他目标未变且旧证据仍适用；构建工具已保存产物位置与版本 | 变更对象按原质量门重验，未变且证据适用的对象复用引用；构建证据记录版本 / 校验值 / 位置，确需受控原始证据时保留 | 为满足正文预算删必要截图；旧图冒充当前状态；无用途重复拷贝二进制；未检查可恢复性就清理原产物 |
| L8 入口过期与恢复 | 续作入口仍指向旧任务状态，而权威源及当前实现已发生变化；原授权和真实依赖限制未解除 | 先核对权威任务与相关当前设计 / 实现 / 依赖，修正获准维护的导航后继续原范围；未授权写文件时只报告不一致 | 照旧摘要直接执行或宣称 done；入口存在即算验证通过；恢复上下文自动解除阻断或放开外部操作 |
| L9 复用现有入口 | 输入一产物目录已有用户约定的入口；输入二 README 还有其他有效内容；输入三入口缺失但当前任务与材料可定位 | 一沿用原入口；二只维护导航小节；三从当前材料恢复最小上下文，把续作记到任务清单（尚无任务则当前方案末尾），不新建入口文件 | 新建多个 resume / progress / summary 文件分别维护状态；覆盖无关 README；以没有入口为由停掉已可执行任务 |
| L10 并行续作与敏感信息 | 同一独立任务的前后端并行，入口导航需要更新；工具上下文含连接凭证 | 两端引用本任务同一权威源，各自更新负责条目；其他独立任务有各自清单，凭证只留在合法工具上下文 | 用项目统一的当前任务覆盖另一任务；在项目和子任务各抄一份状态；把 token / cookie 保存为恢复上下文手段 |
| L11 旧文件不自动清理 | 已有长日志和重复快照；用户只授权规则更新或明确只读，未授权清理迁移 | 仅更新获准范围或只读报告，给出后续整理边界；当前事实、历史证据及回查位置保留 | 为符合新规范删除 / 挪动旧文件、重写历史或自动生成新的全量备份；只读检查也改入口 / 任务 |
| L12 按需加载与规则可达 | 使用产品 / UI 阶段的精简上下文工具，或因工具不可用采用手动回退；任务未影响工程或发布 | 两条路径均能读取通用生命周期工作规则及本阶段模板，先入口和当前任务，再按需查相关片段；工程无关内容不混入 | 精简加载漏掉生命周期约束；为避免遗漏全量读取整个产物树；把文件存在当已读取；为恢复信息抄写全部历史 |
| L13 大需求与模板乘法 | 多个独立业务结果合在一个需求；按每任务复制全阶段模板预计产生数千文件，另一个页面规范预计万行 | 在当前总览拆清单元范围、验收和必要产物；共用约束只留一处，各单元只展开当前阶段详情，canonical 入口保留短索引；不等生成后再处置 | 给每个子任务重建全套目录；把长文切成大量无主题小文件；仅说明复杂就继续膨胀；擅自省掉未完成需求 |
| L14 小需求与已有长文 | A 局部错误文案修订；B 原文很长，本轮仅改一个小段且已有稳定索引 | A 直接做有边界的局部更新；B 定向读取和修改，评估本轮增量，不强制重构全部历史，不新增规模报告 | 任何任务都先拆出多份需求 / 预算文件；因既有文档长而越权搬迁 / 删除；只读任务也改文档 |
| L15 拆分后的规则完整性 | 一个需求按业务主题组织，跨主题共用权限 / 金额 / 事务及验收要求；用户仍要求整体设计完成后开发 | 共用事实只维护一次，长说明主题引用，主文档保留需求 / 验收编号、关系和简短结果以供覆盖核对；按需读取详情，现有检查不支持引用时人工等价核对；原整体交接门禁不变 | 每单元复制并各自修改共同约束；以拆分为名放行未完成的整体设计；为了通过正文检查重复粘贴全部详情 |
| L16 累计体量仍失控 | 各文件都低于复核线，但大量小任务 / evidence 说明累计巨大，主要是重复背景和命令输出 | 按原需求范围复核文件数、累计正文和重复比例；合并稳定主题、复用已有说明及必要证据引用，在获准范围调整组织，保留真实验收 | 以每文件未超线为由继续；把正文移入 evidence 规避；未经授权清理历史或降低验证要求 |
| L17 三份主文档 | 一个有边界的独立任务进入设计并开发，工具没有独立分文件消费要求 | 本任务根目录内维护需求、方案及任务清单，按阶段更新。继承内容引用原事实源，状态、证据和续作只维护在本任务清单 | 把三份文档理解为整个大型项目只能有一套总表；每项实现切片复制全部模板 |
| L18 合并后保留约束 | PRD 合并需求、验收与问题；另一个旧项目保留独立来源；出现同名问题章节或主文档与分文件冲突 | 两种布局均可只读核对；重复编号、明确错误关联、未确认来源及已识别业务阻断仍 BLOCKED，来源冲突 / 同名歧义转人工复核，不能静默挑较乐观版本 | 合并后只检查文件存在；忽略后面的阻断问题；为减文件直接删除旧证据；自动迁移旧项目 |
| L19 条件性独立材料 | 契约由多个端 / 外部共同消费；SQL 需独立执行和回滚审核；正式测试 / 代码审查已经进入阶段 | 引用独立契约与实际 SQL 清单，保留正式报告及必要截图 / 调用证据；每项有唯一事实源 | 为追求三份文件把共享契约、资金 / 权限约束或正式验收证据省略；每个报告再复制一套上游 |
| L20 明确独立返工 | 用户将一次已确认需求下的补充工作明确指定为独立任务，另有普通审查意见仍属于原任务 | 独立任务建立子目录，记录原任务引用、差异及验收，在本地维护进度；普通意见原位处理，保留相关历史 | 独立返工继续往原总日志追加；把每个 finding 自动拆目录；新目录复制整套旧文档或重置旧状态 |
| L21 项目导航与状态归属 | 项目有两个独立任务，均可有 BE-01；用户查询其中一个任务的进展 | 项目索引定位目录，用任务路径和 BE-01 确定条目，只读取该任务及实际共用来源；总览给链接，状态回本地权威源 | 凭 ID 同名混淆任务；按文件时间猜所属目录；在项目总表重复维护同一状态；汇总数量冒充业务完成率 |
| L22 任务切换与仅改实现 | 当前聊天从任务 A 切换到独立任务 B，B 的需求和契约已确认且本轮只修实现 | 重新核对 B 的根目录与范围，引用已有需求 / 契约，必要进度与证据写回 B。本轮未改的阶段无需补造空文件 | 因聊天最初使用 A 而继续写 A；每个阶段退回项目根目录；为独立目录机械新建 PRD、设计、报告全套 |
| L23 共用契约与验收 | A、B 引用同一契约，A 的独立返工改变其中一项状态语义，B 实际消费该项 | 共用契约只有一处当前定义，定向修订 A、B 的适用设计 / 验收和受影响任务结论，保留证据。整体交接与安全要求按原范围核查 | 子目录内复制矛盾契约；任务分开就忽略 B；只标 A done 便宣布整体完成；阻断不受影响的所有任务 |
| L24 既有集中源与工具 | 旧项目集中任务源已有状态与证据且被工具消费，本轮只优化 skill；另一次获准按独立任务迁移 | 本轮保持现有产物；迁移时核对消费者，转移受影响条目并保留 ID / 归属映射、状态和证据，每项仅一份可写源 | 修改 skill 就移动真实文件；父子目录各保留一份可写任务；只因 JSON 存在便生成新 JSON 或同步系统 |
| L25 项目待办派生 | 两个独立任务有同名 ID，一项完成后又重开；项目查询进度 | 各任务维护唯一状态，刷新一份项目 TODO，完成项从视图移除但原证据保留；重开回到视图，目录区分 ID | 手改 TODO；复制 JSON；删除原完成记录；把条目占比报成整体进度 |
| L26 尚未拆解 | 已确认的需求 / finding 尚无任务，另有未经确认的想法 | 原索引按需留简短确认来源；转入本地任务并核对覆盖后移除待拆解行，不另建 backlog | 只汇总已拆解任务造成漏项；自动把想法变成范围；索引与子任务重复维护状态 |
| L27 编码与验收 | 实现任务全部 done，但必要真实验证未通过，父项也未闭合 | 未通过验收在同一清单保留可追踪项，视图仍展示它与未完成父项；验证随实现时明确归属，不造额外验收清单 | 仅因编码 done 清空项目待办；从测试数量猜验收；放松身份 / 资金安全门禁 |
| L28 缺口与兼容 | 索引任务缺文件、表格错列、未知状态，或旧 JSON 权威源无法由通用脚本确认 | 视图与退出码明确不完整，沿真实源人工核对，不猜 schema；已明确本文件权威时可保留无消费者的历史 JSON | 静默略过；旧派生 Markdown 冒充当前；强制迁移现有工具；无待办冒充全覆盖 |
| L29 失败与并发 | 源已更新，写 TODO 失败或生成途中源再被更新；其他独立任务仍可做 | 不回滚源，原视图不冒充最新；拒绝发布混合快照，修复后刷新，继续不依赖视图的工作 | 写出半份视图；失败宣称已清空；为修视图停止全部开发；覆盖其他人的源状态 |
| L30 只读与读取范围 | 只读查询进度，已有索引使用等价路径，项目还保留长日志和示例任务 | 用 --index 定位，--check 只读，滞后则按权威源汇报；只扫描登记范围及直接任务目录，不把代码示例当任务 | 查询即改文档；漏读明确指定但缺失的索引；递归扫描历史生成重复任务；每个子目录另建 TODO |
| L31 既有 TODO 归属 | 项目已有手工 TODO、无标记旧视图或本工具带标记的视图，生成期间目标还可能被其他执行者改写 | 前两者保留并报告归属冲突，带标记视图正常刷新；目标发生变化时拒绝覆盖并保留最新内容 | 按同名或相似正文接管；为了汇总删除旧记录；加默认强制覆盖入口；只保护源却覆盖目标的并发更新 |
| L32 标准标题与未知结构 | 索引和验收标题使用标准关闭井号；另一个索引表位于未知章节 | 前者正确汇总并保留原行号 / 章节边界；后者显式留复核缺口，不猜归属 | 静默漏掉已确认事项并返回成功；把正文 C# 或转义井号误当关闭标记；借用相邻章节 |
| L33 实际来源与冲突 | 声明用任务内 / 项目内相对路径、绝对路径或完整链接指向当前 Markdown；另一声明指向 JSON / 其他文件或含冲突说明 | 按实际路径识别同源，其他来源保留人工核对和真实消费者依据，不猜内容 | 只有“本文件”才接受；因放宽路径就接受所有来源字符串；把旧派生文件当当前源 |
| L34 无关 JSON 与来源变化 | 已明确 Markdown 权威，旧 JSON 编码损坏、变化或删除；另一场景未声明来源且 JSON 存在或生成期间新出现 | 第一种不读取 / 不追踪旧 JSON，视图不因它滞后；第二种明确来源缺口或拒绝发布变化中的视图 | 为消除误报要求修复历史 JSON；解码未知 schema；来源不明仍默认跳过 JSON 并宣布汇总完整 |
| L35 公共原则按需加载 | 单任务想法验证没有使用项目 TODO；另一次确需维护多任务项目视图 | 默认上下文只含公共原则与工具引用，实际维护视图时才加载格式、命令及兼容说明，必要安全 / 验收约束仍在 | 全阶段加载完整工具说明；为了省上下文移掉必要门禁或让真实使用者找不到规则 |

评审记录区分“文档 / 引用结构已检查”“决策人工核对”和“真实恢复 / 外部备份未执行”。不要把本表存在、文件数量下降或短日志本身算作业务交付通过。
