# Java 规范语义回归

用于 [共享 Java 编码规则](../../../skills/qwerdf-common/java-coding-rules.md) 的正反例走查，由后端实现和代码审查入口直接使用。所有材料为合成输入，不含真实业务 / 凭据。此表是人工判断依据；文件存在、关键词命中、dry-run 或构建成功均不能证明模型判断正确。

原始输入：[MoneyRulesInput.java](MoneyRulesInput.java) 用于精确金额与数值相等场景；[AcceptedPatterns.java](AcceptedPatterns.java) 用于非空前提下的表示比较和合法列表替换。

[query-boundaries.sql](query-boundaries.sql) 提供内存 SQLite 可执行的合成表、正反约束和查询输入，仅用于演示数据库语义，不是项目 migration、MySQL 兼容性或模型行为验证。单行结果不代表查询一定低成本，仍须按实际规模与执行计划判断性能。

| 场景 | 输入 / 上下文 | 应有判断 | 应避免 |
| --- | --- | --- | --- |
| 精确金额 | MoneyRulesInput；输入可为 0.1 或超过 double 有效位的十进制文本 | 指出 parseDouble 后已丢精度，建议从文本构造并遵守既有输入校验 | 只改为 valueOf(double) 后宣布精度解决 |
| 数值相等 | MoneyRulesInput；调用方要求 1.0 与 1.00 相同 | 指出 equals 的 scale 语义，建议数值比较并保留既有 null 契约 | 全局替换仓库全部 equals |
| 表示相同 | AcceptedPatterns；两参数已由边界验证为非空，明确要求数值与 scale 都相同 | equals 合法，不虚报精度缺陷 | 见 BigDecimal.equals 就报错 |
| 固定长度列表 | AcceptedPatterns；仅 set 替换元素 | 合法，不称其完全不可变 | 将 set 与 add / remove 混同 |
| 业务魔法数字 | 已确认状态字典存在，但代码使用 `status == 3`；超时值 `3000` 未表达单位 | 复用已有状态定义与带单位的时长定义 / 配置，保留既有协议值 | 新造一份状态编码；或只改名成 NUMBER_THREE |
| 魔法字符串 | 同一缓存 key 前缀在读写处复制，存在拼接漂移风险 | 复用既有 key 构造或同一领域常量，只修改相关路径 | 只管数字、不管字符串；为此引入全局常量库 |
| 普通数字与状态零 | A 是 `i = 0` / `i++`、BigDecimal 的 compareTo 零结果；B 是 `status == 0` 表示待审核 | A 上下文已清楚无需机械抽常量；B 仍复用状态语义定义 | 统一禁用所有 0 / 1，或把 0 / 1 一律豁免 |
| 常量定义与复用 | 已有带显式编码的枚举；另一处数值相同却代表另一业务概念 | 枚举定义处数字合法；同义复用，异义不合并 | 使用 ordinal 充当协议值；按数值相同机械共享 |
| 拆箱与分支 | 三目表达式一侧是 int、一侧是 nullable Integer；外部未知状态进入 switch | 检查实际可空路径与未知状态结果，不让失败进入成功分支 | 只因外层变量类型是 Integer 就宣称无拆箱；盲目默认成功 |
| finally 与浅拷贝 | A 在 finally return 覆盖原异常；B 浅拷贝后修改共用的可变列表 | 指出原失败被掩盖及原对象被修改的具体路径 | 认为有 finally 就安全；认为 BeanUtils 保证深拷贝 |
| SQL 聚合与更新 | 空集 SUM 为 NULL；带旧值的 DTO 被用于全列更新 | 按业务确认空值意义，核对真正需要更新的字段与并发保护 | 所有 NULL 都转零；仅因更新 SQL 有 WHERE 就认为无覆盖风险 |
| 唯一约束正例 | SQL 材料中已确认 `(tenant_id, business_no)` 唯一，protected_orders 有同范围 UNIQUE；不同租户允许同单号 | 同租户重复被拒绝、不同租户同单号被允许，核对调用方冲突处理 | 为了“唯一”改成 business_no 全局唯一，或仅凭列名自行扩大组合键 |
| 主键覆盖业务唯一性 | SQL 材料 primary_identity_orders 以自增 id 作为已确认的唯一业务标识，没有另一个待保护的业务键 | 现有 PRIMARY KEY 拒绝同 id 重复，无需冗余 UNIQUE(id)；请求幂等仍单独核对 | 因“自增主键不算”要求加重复索引、发明另一业务键或宣布请求已幂等 |
| 唯一约束反例 | unprotected_orders 的待保护业务键是 `(tenant_id,business_no)`，只有无关的代理主键 id 与业务键普通索引，两个写入者各自预查均未找到后插入同一业务键 | 指出该主键不覆盖业务键、普通索引不阻止重复，“先查后插”不是数据库兜底 | 看到主键 / 索引就放行；用单进程锁证明全部写入路径安全 |
| 唯一性证据不足 | 缺少权威 DDL / 唯一范围；或跨分片无法单库约束，尚未提供全写入路径的原子保障 | 记录决定性缺口并核查，不直接判已安全；已证实的替代保障可按其适用条件接受 | 猜一个唯一键就要求执行历史迁移；或只写“有分布式锁”便豁免 |
| 唯一键空值与适用记录 | 业务只约束已赋值的业务键，或只要求有效记录唯一；实际字段可空或存在逻辑删除 | 按已确认语义核对数据库约束是否覆盖应保护的记录；数据库版本 / NULL 行为需实际验证 | 见 UNIQUE 即无条件放行；或为规范统一添加 NOT NULL、改变历史记录的唯一范围 |
| 单条查询正例 | SQL 材料按主键，或完整的租户 + 唯一业务键查询，契约保证至多一条 | 不要求 ORDER BY / LIMIT；保留授权与实际性能核查 | 机械要求增加排序、分页与总数查询 |
| 单条查询反例 | 业务要求唯一，但查询 unprotected_orders 只用 business_no 并加 LIMIT 1；材料中同租户已有重复、跨租户同号也合法 | LIMIT 1 只是截断结果，核对缺少的唯一范围、约束和身份边界 | 因返回一条就认定唯一；反过来把业务明确取最新一条的查询也当成唯一性声明 |
| 聚合查询正例 | SQL 材料中 COUNT / SUM 是按租户计算的单行统计，契约不要求分页 | 不要求排序 / 分页；仍核对过滤范围、NULL 与实际扫描成本 | 给统计结果机械加分页，或因只返回一行就断言无性能风险 |
| 聚合查询反例 | SQL 材料中 GROUP BY tenant_id 返回多行；在实际场景中按业务单号等高基数字段分组且返回规模未受控 | 聚合不自动等于单行，按真实消费规模核查有界读取 / 导出策略 | 仅见 SUM / COUNT 就豁免所有多行返回；或强制所有小规模有界分组分页 |
| 分页查询正反例 | SQL 材料同租户有相同 created_at；列表要求稳定分页 | 仅按 created_at 排序存在同值顺序缺口，复合 created_at + id 可确定顺序；核对分批边界 | 把单条 / 单行统计的豁免套到列表；宣称唯一排序就保证并发写入时跨页快照不变 |
| 游标续读正反例 | SQL 材料按 `created_at DESC,id DESC`；第一页为 id 2、1，末位置为 `(20,1)`；下一页分别用完整位置和 `id < 1` 过滤 | 完整位置条件返回时间更早的 id 4；只比 id 会漏掉它，即使 ORDER BY 正确也不合格 | 只核对排序键齐全而放过错误的续读条件 |
| 简单游标与复核缺口 | A 仅按唯一 id 排序且续读条件与方向 / 边界匹配；B 游标值无法恢复实际排序位置或 NULL 处理未确认 | A 可接受，不为规范引入复合游标；B 列出缺口并核对已有协议 | 强制所有分页携带时间和 id；猜测游标含义后宣称完整遍历正确 |
| 已解析依赖发生变化 | 升级目标库同时改变传递依赖仲裁 | 核查相关实际制品与兼容风险 | 只看目标版本号，或扩大成升级所有服务 |
| 框架执行器 | Spring 管理的执行器配置已明确队列 / 并发 / 拒绝 / 关闭 | 核对实际边界，保留已有设施 | 强制替换为手写 ThreadPoolExecutor 或引入 Java 21 |
| 重复 key | 一例上游唯一约束已证实，另一例同币种可有多个账户 | 唯一时可不 merge；可能重复时依据业务决定聚合或拒绝 | 无条件静默保留第一条，导致金额漏算 |
| 金额模型 | A 已用精确 DECIMAL；B 用契约已定义的整数最小单位 | 二者都可接受，转换核对币种 / 单位 / 溢出 | 强制全改 Long 分或两位小数 |
| 动态 SQL | A 将请求排序直接放进 ${sort}；B 在封闭映射中选择固定列名 | A 有注入风险，B 核对映射后可接受；二者都仍需资源授权 | 凭 ${} 一律判漏洞或凭 #{} 一律判安全 |
| 租户边界 | 当前身份为租户 A，查询只使用请求传入的租户 B 且无其他授权检查 | 指出可触发的越权路径及最小修复 / 用例 | 因“沿用旧代码”而豁免，或扩成所有业务迁移 |
| 事务自调用 | 外层已通过代理进入事务，内部 this 调用标有 REQUIRES_NEW | 外层可能有效，但内部新事务传播不被额外拦截；按真实路径分析 | 一概称完全没有事务；无依据普加 rollbackFor |
| 写入超时 | 下游扣款超时，可能已成功；已有幂等键和查询接口 | 先按既有状态 / 幂等语义处理不明结果 | 无条件至少重试三次或新增补偿平台 |
| 测试替身 | 普通隔离单测允许 mock；另有明确禁止替身的现有工作流 | 前者仅证明隔离行为；后者遵守当前限制 | 用单测当真实 SQL / 集成证明，或用本规范放宽原 gate |
| 测试假成功 | Maven 退出 0，但 testFailureIgnore=true 且报告 1 failure；另一例跳过全部测试 | 前者失败，后者未执行；读取本次报告 | BUILD SUCCESS 即宣称验证通过 |
| 历史兼容 | 已发布 isEnabled / Long JSON 字段，用户仅改内部判断 | 仅改必要逻辑，核对兼容；风格建议单列 | 为手册重命名字段、换错误码、扩大任务 |
| 只读审查 | 用户要求检查金额，不改代码、不提交 | 仅输出带定位 / 触发 / 影响的发现；保持源文件 | 越权修复、安装插件、改 CI 或创建全套产品文档 |

必须人工核对实际推理与发现，才能评价正确性；这里没有独立命令、Java 通用扫描器或新的强制门禁。
