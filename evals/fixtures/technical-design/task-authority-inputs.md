# 合成任务来源快照

用于 T5 的输入：本例已确认现有消费者读取 JSON，JSON 为权威源，各端顺序由 owner 内的 order 字段确定，Markdown 只为派生视图；证据描述也属于本例输入，不代表真实系统已经验证。评审 T6 时不沿用这些已确认条件。字段只是既有结构的一种例子，不是通用 schema 或新的状态文件要求；数组顺序已是权威约定的项目无需增加 order。

## 权威 JSON 输入

```json
[
  {
    "id": "BE-001",
    "owner": "backend",
    "order": 1,
    "status": "done",
    "task": "保存配置并返回实际结果",
    "acceptance": "真实持久化、本端接线、权限与失败反馈检查",
    "evidence": "合成证据：本端检查通过；真实跨端验收另记"
  },
  {
    "id": "BE-002",
    "owner": "backend",
    "order": 2,
    "status": "pending",
    "task": "读取已保存配置",
    "acceptance": "按确认契约验证可见范围和返回值",
    "evidence": "尚未实现"
  },
  {
    "id": "FE-001",
    "owner": "frontend",
    "order": 1,
    "status": "in_progress",

    "evidence": "本端契约与工具链已就绪，页面接线尚未完成"
  }
]
```

## 正例：从权威输入刷新后的视图

```markdown
任务来源：已确认 JSON；本文件为派生视图。状态更新写回该 JSON 后再刷新。

## 前端任务

| 顺序 | ID | 业务动作与交付结果 | 状态 | 完成标准 | 证据 / 阻断 |
| --- | --- | --- | --- | --- | --- |
| 1 | FE-001 | 配置编辑页接入真实 client | in_progress | 本端页面接线、状态处理与构建 / UI 检查 | 本端契约与工具链已就绪，页面接线尚未完成 |

## 后端任务

| 顺序 | ID | 业务动作与交付结果 | 状态 | 完成标准 | 证据 / 阻断 |
| --- | --- | --- | --- | --- | --- |
| 1 | BE-001 | 保存配置并返回实际结果 | done | 真实持久化、本端接线、权限与失败反馈检查 | 合成证据：本端检查通过；真实跨端验收另记 |
| 2 | BE-002 | 读取已保存配置 | pending | 按确认契约验证可见范围和返回值 | 尚未实现 |

## 联调 / 测试范围
- 配置保存和回读：关联 FE-001、BE-001、BE-002；真实输入 ready 后按原验收验证，不复制开发状态。
```

核对 ID、归属、顺序、状态、完成标准及证据，不只核对任务数量。JSON 中 done 仅代表该任务原完成条件已满足，不证明整个业务链路或上线验收通过。前端按契约独立推进，不等整端后端完成；反例快照用于复现差异，不是允许维护第二套权威数据。
