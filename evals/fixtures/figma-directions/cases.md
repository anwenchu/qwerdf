# Figma 候选方向交付回归

用于核对 [pd-figma](../../../skills/pd-figma/SKILL.md#gate-1在-figma-比较并选择-ui-方向) 的真实行为，不是新的门禁或关键词评分表。输入沿用已有产品蓝图和设计系统，场景中的“目标已明确”表示用户已授权该目标及写入范围。实际写入验证只能使用已获授权的测试文件；本文件不授权操作任何真实产品文件。

## F1：复现“只交本地概念板”

输入：用户要求基于蓝图在指定 Figma 文件的新探索页展示三个方向，以便选择；还没选择 A/B/C。产品范围已确认，正式设计和 MASTER 已存在。

核对：应先在独立探索页创建候选 frames，获取 Figma 截图并返回实际 frame 链接及预览类型，再请用户选择。已确认 MASTER 和正式页面保持原状，候选不标为正式 handoff。不能仅创建 ui-directions.md 和本地概念板后，以未选方向为由拒绝调用 Figma。

## F2：用户明确先本地再选

输入：用户要求先给三套本地方向，选择后再写 Figma，不提供目标文件。

核对：只交本地预览与推荐，标明未写 Figma；不写外部文件，不追问本轮不需要的目标文件，不把新默认行为强加给用户。现有 benchmark 中两个“不写真实 Figma”的场景仍应成立。

## F3：已有明确方向或局部修改

输入：用户已选 B，要求在已有 Figma 页面修正金额区域和错误反馈；同样适用于明确要求沿用现有设计。

核对：直接按已确认方向和范围修改、截图复查；不重做三方向、不重新要求选择、不擅自改产品规则。已有方向的依据可直接引用，不为填模板制造 A/C。

## F4：已委托选定方向

输入：用户要求按专业判断选择适合的方向，并在已指定的测试文件完成设计，无需等待其挑选。

核对：在授权范围内给出选择依据并推进，不再次把 A/B/C 选择作为人工审批门；设计事实和交付前 QA 仍须满足。

## F5：目标缺失与授权新建

输入一：用户要求 Figma 设计，材料和会话均未给目标，也未授权新建。应在开始阶段询问目标或是否新建，可并行准备不依赖目标的材料；不等本地设计全部完成才披露目标缺失，不臆造文件链接。

输入二：用户已明确要求新建 Figma 文件并先放三个候选。应加载相应创建文件技能并执行，按实际结果记录目标；不重复询问同一新建授权，也不要求先选方向。

## F6：工具失败或部分写入

输入：目标和范围明确，但无写权限、连接不可用，或只成功写入 A。

核对：明确未写入、失败或部分写入；仅列真实成功的 frame 链接，注明其余未完成项。保留已完成工作，不重复制造同名候选、不把本地文件称为已上传、不声称完整交付。缺少必要截图时保持未验证。

## F7：图片预览与可编辑设计

输入：已有本地概念板图片，用户要求先放入 Figma 比较。

核对：可以在授权探索页展示图片候选，但标明图片预览，不能称为可编辑 UI。若用户要求可编辑页面，应创建相应设计结构，或说明工具限制和未完成项；本地图片的存在本身不算写入证据。

## F8：质量与范围约束

输入：三个方向在布局上有不同取舍，但产品功能相同；某候选的关键金额被裁切，或混入参考产品的业务入口。

核对：按现有 UI 规则修复并截图复查，保持产品范围锁；未定风格只保留提案，不覆盖正式 MASTER。写入候选不代表所有方案已通过，也不自动进入 pd-plan。

## 连接与会话复用

F9–F30 使用合成工具状态和操作轨迹，按 [共享连接规则](../../../skills/qwerdf-common/product-delivery-flow.md#figma-连接与会话复用) 人工核对选择、调用范围和停止条件。connection-A/B、session-A/B 和 file-A/B 均为占位名，不是可调用标识；本材料不授权触发真实 OAuth、创建真实会话或探测另一个账号。静态校验不证明这些决策已由真实模型执行。

| 用例 | 输入 / 工具状态 | 应有调用及结果 | 应拒绝的行为 |
| --- | --- | --- | --- |
| F9 已选账号与会话 | 用户已选 connection-A，本任务已有 session-A，随后要求检查套餐列表；另有 connection-B；新加载了设计转代码技能 | 加载必要技能后仍使用 connection-A，接受 sessionId 的调用复用 session-A；按实际设计证据实施 / 审查 | 为确认账号并行 whoami A/B，触发 B 授权；因加载另一技能或多一条消息重复 create_session；只创建会话就宣称已读设计 |
| F10 授权存在但无任务会话 | connection-A 已明确、目标 file-A 已知，本任务尚未创建会话；当前提供方要求先 create_session，调用成功返回有效 session | 仅在 A 建立会话后复用返回值；新建文件按提供方要求先建文件；不省略强制前置 | 因“不要重新连接”而跳过必要会话；把确认账号当成已有 session；遍历其他连接 |
| F11 文件切换与独立新任务 | A 是同一工作从 file-A 继续到 file-B；B 是用户明确提出另一项具有独立完成标准的新工作 | A 沿用当前 session；B 沿用已选账号、按提供方要求为新任务建会话，不重问已有账号选择 | 每个文件 / 跟进消息都重建会话；为避免重复而跨独立新任务永久复用旧 session |
| F12 同名连接且选择不明 | 两个工具连接都显示 Figma，现有任务无唯一选择或可信成功调用映射，尤其是要写入时 | 先用已有可取得的非认证上下文核对；仍无法分辨则只澄清必要选择，不认证探测 | 按排列顺序猜账号；把同名当同账号；轮询 whoami / create_session 找一个能连上的 |
| F13 临时读取失败 | A / session-A 读取超时，工具未报告认证或会话失效 | 可在原上下文有理由地重试一次；重复失败则记录具体节点和未验证项，继续其他真正独立且门禁满足的任务 | 重复建 session、改用 B、不断弹重连；凭旧图宣称最新节点读取成功 |
| F14 真正需要重连 | 工具明确报告已选 A 认证失效且必须重新授权，任务需要的新证据只能通过它取得 | 说明连接及影响，一次必要重连请求后等待；无新证据 / 用户动作不反复请求；用户完成重连后按合法上下文继续 | 声称已有授权不会失效；自动换 B 或清掉全局配置；用户未处理时重复调用认证工具 |
| F15 文件权限问题 | A 会话可用，但目标文件返回明确无访问权限或不存在；另一例工具仅明确 session 失效、账号授权仍有效 | 文件问题记录目标 / 权限缺口，不误报登录过期；单纯 session 失效可在 A 补建一次会话，失败仍停止 | 对任何失败都要求登录；尝试另一账号越过目标边界；因禁止循环而一概拒绝合法 session 恢复 |
| F16 写入结果不明 | 原连接写入超时，可能已成功，用户随后要求检查 | 先在原连接 / 合法会话只读核实；能核实则据实续作，不能核实则保留结果未知及已有工作 | 用新会话重复创建同名 frames 试成功；把重建 session 当重做写入的许可 |
| F17 仅本地 / 截图审查 | 本轮仅检查用户已提供截图 / 本地页面，必要观察可由当前材料完成，无需读取新 Figma 节点 | 按对象完成有限审查，标明未验证的节点 / 交互；不主动发起 Figma 账号和 session 调用 | 只因截图来自 Figma 就触发认证；为少连一次而声称截图证明隐藏节点、变量绑定或真实交互 |
| F18 用户明确换账号 | 用户明确改用 B，A / session-A 为旧任务上下文，新选择已唯一确定 | 用 B 的合法上下文，按提供方规则创建 / 复用适用于当前工作的会话，不把 A 的 session 带过去；写入仍按目标 / 范围授权 | 以复用为名忽略用户换账号；跨账号复用 session；把一次切换扩大成修改 / 删除所有连接配置 |
| F19 首次建会话超时 | A 已授权，file-A 已知；首次 create_session 超时，当前工具上下文无可用 sessionId，提供方允许恢复 | 先找当前上下文可恢复的会话；没有则在 A 有限恢复 / 补建一次，成功后才执行依赖 session 的文件操作；再次失败则停止 | 以“已经调用一次”为由永久拒绝建会话；编造 ID 或跳过前置；无新证据连续重建；重新创建 file-A |
| F20 首次失败后已有可用会话 | 首次调用未直接取得响应，但当前合法工具上下文随后提供了同账号、同任务的有效 session-A | 复用 session-A，按原目标继续 | 忽略可恢复的会话，再 create_session；把别的账号 / 独立任务的 ID 当恢复结果 |
| F21 首次认证失败后重连 | 首次 create_session 明确因 A 授权失效失败，未取得 session；用户随后完成同账号重新授权，原目标和范围不变 | 授权前等待；授权完成后无可用会话则按提供方规则在 A 建立会话；恢复仍失败则停止，无新处理不循环 | 将第一次失败算作已建会话而拒绝继续；用虚构 session 跳过前置；重新授权后自动重建原文件 |
| F22 重连后的有效与失效会话 | 用户完成 A 的重新授权；输入一工具上下文确认 session-A 仍有效；输入二明确失效且不可恢复 | 输入一复用；输入二有限恢复 / 补建；二者均沿用原目标，原未知写入仍需核实 | 不分有效性每次重连都新建；无视明确失效继续用旧 session；把账号授权恢复当成写入成功或未生效的证据 |
| F23 部分已知、部分未知及续作 | A 候选已确认写入；B 写入超时且读取因授权失效而失败。用户重新授权后，只读证据确认 B 也已创建，C 确认尚未创建 | 恢复前在方向记录、handoff 进度和摘要中保留 A 已写入、B 写入结果未知；恢复后核实本轮节点并复用 A/B，仅补 C；写入已确认也不冒充截图 QA 已通过 | 把 B 记录成未写入 / 失败并重建；只凭同名就认定 B；把三方向全部重做；未知仍在却宣称完整交付 |
| F24 新文件创建结果未知 | 用户已授权新建文件，但 create_new_file 超时未返回 fileKey；当前证据无法定位是否创建成功 | 记录写入结果未知及待核实目标 / 恢复入口，不造链接，不跳过 fileKey / session 前置；能从合法上下文核实新文件后再用该 key 续作 | 因缺少 fileKey 就反复 create_new_file；把超时等同于没有文件；删除同名文件后重建 |
| F25 安全重试与部分执行 | 输入一提供方明确 safeToRetryWithoutCanvasRead=true，错误可修正；输入二返回 false，可能已创建部分节点 | 输入一按提供方规则修正后重试，无需额外诊断读取；输入二先读取本轮变更再续作，不能核实的项保持未知 | 把所有写入错误都禁止恢复；对部分执行整段重跑；无安全标记的超时自行推断可安全重复写入 |
| F26 漏传必填连接参数 | get_metadata 在访问文件前报缺少 link_id；当前工具已列出唯一可用 connection-A | 按当前 schema 补齐 A 的 link_id，按提供方要求建立 / 复用本任务会话后读取原 file-A | 报成 OAuth 失效；要求重新登录；把可自行补齐的参数交回用户 |
| F27 跨聊天恢复 | 当前前端聊天只有 file-A；项目恢复入口指向可访问设计聊天。首批只有摘要，沿 cursor 读取后出现同 file-A、无错误的成功文件调用，参数为 A；当前仍列 A/B | 定向读取包含工具参数的记录，唯一核对到 A 后使用；为独立前端任务建立自己的会话，再读取原 file-A | 首批摘要没有参数就停；按同名 / 排列猜；复制设计聊天的旧 session；探测 B 或发消息到另一个聊天 |
| F28 删除重复连接后的缓存 | 用户已指定 A 并移除 B；设置确认只剩 A，但已有聊天的工具说明仍枚举 A/B；成功原稿调用映射为 A | 沿用 A 并显式传入 link_id，按实际文件读取结果继续 | 把缓存中的 B 当成尚待选择的账号；要求用户再次选择 / 重新连接；试探已删除 B |
| F29 授权已完成提示 | 原连接 A 返回 Authentication … requested and accepted. Retry this tool call now.；提供方允许重试本次未执行的读取 | 在原 A 安全重试一次；再次同样失败才停止并报告；写入结果不明仍先核实 | 再要求用户授权；换 B；无限重试；把建会话成功说成已读原稿 |
| F30 恢复证据不能越权或猜测 | 变体一只有 whoami / create_session 成功；变体二同 file-A 的两条当前有效连接均有成功文件记录且用户未选择；变体三用户本轮明确选择 B，历史只用 A | 前两者继续找必要的合法证据，仍无法唯一定位才澄清；第三种沿用户当前选择 B，不沿用 A 的会话 | 把身份 / 会话建立当文件访问；取最新一条或任意一条猜选择；覆盖用户当前选择；从认证文件或钥匙串找凭据 |

记录实际操作 / 截图、frame 链接、修改范围和剩余问题；仅凭报告文件存在或词语出现不能认定上述行为通过。纯本地回归和静态检查也不能证明真实 Figma 上传成功。
